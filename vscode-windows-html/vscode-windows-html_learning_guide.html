How to use this guide — you do NOT have to start at Module 1.1
This guide is built to be non-linear. Each module is self-contained with its own prerequisites, skip-check, and outcomes. If you already have VS Code installed, jump straight to Phase 2 and start editing. Use the Placement Quiz below to find your entry point, or the Module Index to jump anywhere. Every exercise builds the same running example: a personal web page called about-me.html.

Quick Start: Three Ways to Use This Guide

  1. Never installed a code editor → Start at Module 1.1 and go sequentially.
  2. Already have VS Code open → Take the Placement Quiz (next section) to find your entry point, or skip to Phase 2.
  3. Just need one skill (e.g. "how do I preview my HTML?") → Jump via the Module Index or Learning Tracks.

Phase 1: Install & Launch VS Code

Day 1 | Goal: Get VS Code downloaded, installed, and open on your Windows PC.

Module 1.1 — Download VS Code for Windows

Level: Beginner · Prereqs: None · Time: ~0.5h
Skip-check (test-out): Download the correct .exe for a normal Windows account (no admin rights) and explain why you chose it.
Skip if: You already have the installer downloaded or VS Code installed.
Unlocks: Module 1.2

What VS Code is (and isn't)

Visual Studio Code ("VS Code") is a free, lightweight code editor made by Microsoft. It is a sophisticated text editor for code — it does not run your website for you, and it is not the same as the much heavier "Visual Studio" IDE. Confusing the two leads beginners to download gigabytes they don't need, so make sure you are on the right site: code.visualstudio.com.

The current stable release as of this guide is version 1.129 (July 2026). Versions update roughly monthly; the download page always serves the latest, so you never need to hunt for a version number.

Go to the official download page

Open your web browser and go to https://code.visualstudio.com/download. Downloading from anywhere else (a random "free download" mirror) risks bundled malware — the trap here is that fake VS Code installers are a common way to get tricked into installing something harmful, so only trust the official Microsoft domain.

On the download page you'll see a large Windows button. Below it are the specific options.

User Installer vs. System Installer — pick the right one

Windows offers three shapes of the same editor. This choice trips up almost every beginner, so here is the plain-English version:

OptionWhat it doesChoose it when
User InstallerInstalls VS Code just for your Windows account, in your user folder. No administrator password needed. Updates install quietly in the background.Almost always — this is the recommended default.
System InstallerInstalls for all users on the PC. Requires an administrator password.A shared/lab computer where every account should have it.
.zip archiveA "portable" copy you unzip yourself — no installer, no Start-menu entry.Advanced use (running from a USB stick). Not for beginners.

For a personal Windows laptop, download the User Installer (x64). The file it saves is named like VSCodeUserSetup-x64-1.129.exe. If your PC is a newer ARM-based machine (e.g. some Surface models) choose the Arm64 User Installer instead; if you're unsure, x64 works on the vast majority of Windows PCs.

Common mistake: Downloading "Visual Studio Community" instead of "Visual Studio Code." They are different products from the same company. You want the small one called Code.

Exercise 1.1 — Get the right installer

Running example: preparing to build about-me.html.

  1. Open your browser and navigate to https://code.visualstudio.com/download.
  2. Confirm the address bar shows the exact domain code.visualstudio.com with a padlock.
  3. Click the Windows User Installer download (x64, unless you know you have an Arm64 machine).
  4. Find the downloaded file in your Downloads folder and confirm its name starts with VSCodeUserSetup.
  5. Write down one sentence: why is the User Installer the right pick for your own laptop?

Module 1.2 — Run the Installer & First Launch

Level: Beginner · Prereqs: 1.1 · Time: ~0.5h
Skip-check (test-out): Launch VS Code from the Start menu and open a folder — proving it installed and is on your system.
Skip if: VS Code already opens from the Start menu.
Unlocks: Module 1.3

Run the setup wizard

Double-click the VSCodeUserSetup-x64-1.129.exe file you downloaded. Windows may show a blue "Windows protected your PC" SmartScreen box the first time — because the file is new to your machine, not because it's unsafe. Click More info → Run anyway. (This is safe only because you downloaded from the official Microsoft site in Module 1.1 — never click "Run anyway" on a file from an unknown source.)

The checkboxes that matter

Accept the licence agreement, keep the default install location, and then you reach the "Select Additional Tasks" screen. Here is what to tick and why:

CheckboxRecommendationWhy it matters
Create a desktop iconOptionalConvenience only.
Add "Open with Code" to file context menuTick bothLets you right-click any folder in File Explorer and open it instantly in VS Code — a huge time-saver you'll use constantly.
Register Code as an editor for supported file typesTickDouble-clicking a .html or .txt file can open it in VS Code.
Add to PATHLeave ticked (default)Lets you type code . in a terminal to open the current folder. You'll appreciate this later; leaving it off means a confusing "command not found" down the road.

Click Install, wait a few seconds, and let it finish. Tick Launch Visual Studio Code on the final screen, then Finish.

Confirm it's really installed

Close VS Code, then press the Windows key and type code. "Visual Studio Code" should appear as a Start-menu result. If it does, the installation is complete and reproducible — you can now open it any time without the installer.

Exercise 1.2 — Install and verify

  1. Run the installer and tick Add "Open with Code" for both files and directories.
  2. Leave Add to PATH ticked. Finish the install.
  3. Launch VS Code; when it opens, you'll see a "Welcome" tab — that's expected.
  4. Close it, press the Windows key, type code, and re-open it from the Start menu.
  5. In File Explorer, right-click any folder and confirm you now see "Open with Code" in the menu.

Module 1.3 — Tour the VS Code Window

Level: Beginner · Prereqs: 1.2 · Time: ~0.5h
Skip-check (test-out): Point to the Activity Bar, Explorer, Editor area, and Command Palette without looking them up.
Skip if: You can already name the main regions of the VS Code window.
Unlocks: Phase 2, Module 3.3

The five regions you'll actually use

When VS Code opens, the window is divided into a handful of areas. Knowing their names means every tutorial you ever read will make sense — instructions like "click the Explorer" become obvious instead of mysterious.

RegionWhereWhat it's for
Activity BarFar-left vertical strip of iconsSwitches big panels: Explorer (files), Search, Source Control (git), Run, Extensions.
Explorer / Side BarLeft panelThe file tree of your open folder — where you create and open files.
EditorBig central areaWhere you actually type and edit your code. Files open as tabs across the top.
PanelBottom (toggle with Ctrl+`)Terminal, Problems, and Output. You can ignore it for now.
Status BarThin bar at the very bottomShows the language mode (e.g. "HTML"), line/column, and encoding.

The Command Palette — your master shortcut

Press Ctrl+Shift+P. A search box drops down from the top: this is the Command Palette, and it can run every command in VS Code by name. If you ever forget a shortcut, open the palette and type what you want ("format", "install extension", "open folder"). Learning this one shortcut means you never have to memorise the rest.

Retrieval practice: before reading on, try to name the far-left strip of icons and the big central area from memory. Naming them now — rather than re-scanning the table — is what fixes them in memory.

Pick a theme (optional, 30 seconds)

Open the Command Palette (Ctrl+Shift+P), type Color Theme, press Enter, and use the arrow keys to preview light and dark themes. A comfortable theme reduces eye strain over long sessions — pick whichever you'll actually enjoy looking at.

Exercise 1.3 — Name the window

  1. Open VS Code. Hover over each icon in the far-left Activity Bar and note its tooltip name.
  2. Click the top icon (Explorer). Notice it currently says "You have not yet opened a folder."
  3. Open the Command Palette with Ctrl+Shift+P, then press Esc to close it.
  4. Toggle the bottom Panel open and closed with Ctrl+` (the backtick key, above Tab).
  5. Switch to a Color Theme you like via the Command Palette.

Phase 2: Editing Your First Code File

Day 1–2 | Goal: Create, write, save, and confidently edit an HTML file.

Module 2.1 — Open a Folder as a Workspace

Level: Beginner · Prereqs: 1.3 · Time: ~0.5h
Skip-check (test-out): Create a folder my-first-site, open it in VS Code, and see it named at the top of the Explorer.
Skip if: You already open folders and see files in the Explorer.
Unlocks: Module 2.2

Why VS Code works on folders, not loose files

VS Code is happiest when you open a whole folder (it calls this a "workspace"), not a single file. A real project is a folder of related files — your HTML, images, and stylesheets all live together. Opening the folder lets the Explorer show them side by side and lets features like Live Server work. Open just a loose file and half of VS Code's helpfulness is switched off.

Create your project folder

First, make a folder for this guide's running example. In File Explorer, go to your Documents, create a new folder named my-first-site. Then, in VS Code, choose File → Open Folder… (or press Ctrl+K then Ctrl+O), select my-first-site, and click Select Folder.

The Explorer on the left now shows MY-FIRST-SITE at the top. It's empty — that's exactly right; you'll add the file next. If VS Code shows a "Do you trust the authors of the files in this folder?" prompt, click Yes, I trust the authors for folders you created yourself. This trust prompt exists because opening someone else's project can run code, so only trust folders whose contents you know.

Exercise 2.1 — Open the workspace

Running example: the my-first-site folder that will hold about-me.html.

  1. Create a folder my-first-site inside your Documents.
  2. In VS Code, use File → Open Folder… to open it.
  3. Confirm the Explorer shows MY-FIRST-SITE at the top.
  4. Click Yes, I trust the authors if prompted.
  5. Tip: close the Welcome tab so the editor area is clear.

Module 2.2 — Write & Save an HTML File

Level: Beginner · Prereqs: 2.1 · Time: ~1h
Skip-check (test-out): Create about-me.html, type a valid HTML skeleton, and save it with no unsaved-changes dot on the tab.
Skip if: You can already create, write, and save an HTML file confidently.
Unlocks: Module 2.3, Module 3.1

Create the file

In the Explorer, hover over the MY-FIRST-SITE heading — a row of small icons appears. Click the New File icon (a page with a "+"). Type the name about-me.html and press Enter. The .html extension is what tells VS Code "this is HTML" — get it wrong (e.g. about-me.txt) and you lose color highlighting and the browser won't treat it as a web page.

Type your first HTML

An HTML file has a standard skeleton. Type the following into about-me.html (typing it out, rather than pasting, is how it sticks):

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <title>About Me</title>
  </head>
  <body>
    <h1>Hi, I'm Alex</h1>
    <p>This is my very first web page, built in VS Code.</p>
  </body>
</html>

Each part has a job: <!DOCTYPE html> tells the browser this is modern HTML; <head> holds information about the page (like its <title>); <body> holds what you actually see. The <h1> is a big heading and <p> is a paragraph.

Save it — and know when it's unsaved

Look at the file's tab. When you have unsaved changes, VS Code shows a solid dot instead of the little "x" on the tab. Press Ctrl+S to save; the dot turns back into an "x". Unsaved work is the single most common beginner frustration — you preview the page, nothing changed, because the edit was never saved. Get in the habit of pressing Ctrl+S constantly.

Tip: Turn on File → Auto Save to have VS Code save for you after a short pause. Many beginners enable it on day one to sidestep the "why didn't my change show up?" trap entirely.

Exercise 2.2 — Your first page

Running example: about-me.html.

  1. Create about-me.html in the my-first-site folder.
  2. Type the HTML skeleton above (type it, don't paste).
  3. Change the <h1> to your own name and edit the paragraph text.
  4. Add a second paragraph: <p>I am learning to code.</p>
  5. Save with Ctrl+S and confirm the tab's dot becomes an "x".
  6. Deliberately type a character, watch the dot appear, then save again.

Module 2.3 — Editing Essentials

Level: Beginner–Intermediate · Prereqs: 2.2 · Time: ~1h
Skip-check (test-out): Use undo/redo, Find & Replace, multi-cursor, and one Emmet expansion in a real file.
Skip if: You already use multi-cursor and Emmet comfortably.
Unlocks: Track 3

The everyday editing shortcuts

These are the keystrokes you'll use thousands of times. Learning them now saves hours later — reaching for the mouse for every edit is what makes coding feel slow.

ActionShortcutNotes
Undo / RedoCtrl+Z / Ctrl+YYour safety net — edit fearlessly.
SaveCtrl+SDo it constantly.
FindCtrl+FSearch within the file.
Find & ReplaceCtrl+HSwap one word for another everywhere.
Add cursor to next matchCtrl+DSelect a word, press again to grab the next identical word — edit them all at once.
Move line up/downAlt+↑ / Alt+↓Reorder lines without cut/paste.
Copy line downShift+Alt+↓Duplicate a line instantly.
Comment / uncommentCtrl+/Toggle the current line as a comment.

Emmet — type less HTML

VS Code has Emmet built in (no install needed). It expands short abbreviations into full HTML. In an empty .html file, type an exclamation mark ! and press Tab — VS Code writes an entire HTML skeleton for you. Type ul>li*3 and press Tab to get a list with three items:

<!-- typing  ul>li*3  then Tab  produces: -->
<ul>
  <li></li>
  <li></li>
  <li></li>
</ul>

Emmet turns tedious typing into a couple of keystrokes; it's one of the biggest reasons developers write HTML fast.

Common mistake: Nothing happens when you press Tab after !. Almost always the file isn't recognised as HTML — check the language mode in the bottom-right Status Bar says HTML. If it says "Plain Text," you probably saved the file without the .html extension.

Exercise 2.3 — Edit like a pro

Running example: about-me.html.

  1. Use Ctrl+D to select every occurrence of a repeated word and change them all at once.
  2. Use Ctrl+H to replace your name with a nickname, then undo it with Ctrl+Z.
  3. Duplicate your <p> line with Shift+Alt+↓ and edit the copy.
  4. Below your paragraphs, type ul>li*3 and press Tab; fill the three list items with three hobbies.
  5. Reorder two lines using Alt+↑ / Alt+↓.
  6. Save and confirm the Status Bar shows the language as HTML.

Phase 3: See It Work & Build Good Habits

Day 2 | Goal: See your page in a real browser, keep it tidy, and set up a comfortable editor.

Module 3.1 — Preview HTML in the Browser

Level: Beginner · Prereqs: 2.2 · Time: ~0.75h
Skip-check (test-out): Open about-me.html in a browser and see edits auto-reload after saving.
Skip if: You already use Live Server or Live Preview with auto-reload.
Unlocks: Module 3.2

The simplest way: open the file in a browser

Your HTML file is just a file on disk. Find about-me.html in File Explorer and double-click it (or drag it onto an open browser window). It opens in your default browser and shows your heading and paragraphs. To see a change, you'd edit, save, and manually refresh the browser — which gets tedious fast.

The better way: Live Server (auto-reload)

Live Server is an extension that serves your page and automatically refreshes the browser every time you save. This tight edit → save → see-it-instantly loop is the single biggest boost to how fast you learn, because you get immediate feedback on every change.

Install it:

  1. Click the Extensions icon in the Activity Bar (the four-squares icon), or press Ctrl+Shift+X.
  2. Search for Live Server (by Ritwick Dey).
  3. Click Install.

Then, with about-me.html open, either click "Go Live" in the bottom-right Status Bar, or right-click the file and choose "Open with Live Server." Your browser opens at an address like http://127.0.0.1:5500/about-me.html. Now edit the <h1>, press Ctrl+S, and watch the browser update on its own.

Alternative: Microsoft publishes its own extension called Live Preview that shows the page in a panel inside VS Code. Either works; Live Server is the long-standing beginner favourite, so this guide uses it. Don't run both at once on the same file — pick one.

Exercise 3.1 — See it live

Running example: about-me.html.

  1. Install the Live Server extension.
  2. Open about-me.html and click Go Live in the Status Bar.
  3. In VS Code, change your <h1> text and press Ctrl+S.
  4. Watch the browser refresh automatically — no manual reload.
  5. Add a new hobby to your list, save, and confirm it appears instantly.
  6. Stop the server by clicking the "Port: 5500" indicator in the Status Bar.

Module 3.2 — Auto-format with Prettier

Level: Beginner–Intermediate · Prereqs: 3.1 · Time: ~0.75h
Skip-check (test-out): Take a messy, badly-indented HTML file and clean it up with one Format Document command.
Skip if: You already format on save with Prettier.
Unlocks: Module 3.3

Why formatting matters

As your file grows, inconsistent indentation makes it hard to see which tag is inside which. A formatter fixes spacing and indentation automatically so the structure is obvious at a glance — you spend your attention on the code, not on lining things up by hand.

Install Prettier and format

  1. Open Extensions (Ctrl+Shift+X), search Prettier - Code formatter (by Prettier), and Install.
  2. Open a messy HTML file, then press Shift+Alt+F (Format Document). Everything snaps into clean, consistent indentation.
  3. The first time, VS Code may ask which formatter to use — choose Prettier.

Watch what "Format Document" does to sloppy input:

<!-- before -->
<body><h1>Hi</h1><p>messy
   and    crooked</p></body>

<!-- after Shift+Alt+F -->
<body>
  <h1>Hi</h1>
  <p>messy and crooked</p>
</body>

Format on save (set it once)

Even better, have VS Code format every time you save. Open the Command Palette (Ctrl+Shift+P), type "Preferences: Open Settings (UI)", search Format On Save, and tick the box. Now every Ctrl+S both saves and tidies — your files stay clean without a second thought.

Exercise 3.2 — Tidy up

Running example: a deliberately messy copy of about-me.html.

  1. Install Prettier.
  2. Squash a few lines of your HTML together and mangle the indentation on purpose.
  3. Press Shift+Alt+F and watch it snap back to clean formatting.
  4. Enable Format On Save in Settings.
  5. Make another mess, then just press Ctrl+S and confirm it auto-formats.

Module 3.3 — Extensions, Themes & Good Habits

Level: Beginner · Prereqs: 1.3 · Time: ~0.75h
Skip-check (test-out): Install, disable, and uninstall an extension, and explain what a bloated extension list costs you.
Skip if: You already manage extensions and know the core habits.
Unlocks: Final Capstone

Managing extensions

The Extensions view (Ctrl+Shift+X) is the Marketplace. Each extension you install adds features — but every one also adds a little startup cost and clutter. Install deliberately: too many extensions can slow VS Code down and cause conflicts, so add one when you have a real need, not "just in case." You can Disable an extension without removing it, or Uninstall it entirely from the same panel.

A sensible beginner starter set is just three: Live Server, Prettier, and (optionally) an icon theme for a nicer file tree. That's genuinely enough to build real pages.

Habits that make you faster

  • Save constantly (Ctrl+S) or turn on Auto Save — the number-one fix for "my change didn't show up."
  • Open a folder, not a loose file — so the Explorer and Live Server work properly.
  • Learn the Command Palette (Ctrl+Shift+P) — it replaces memorising dozens of shortcuts.
  • Let Prettier format on save — never hand-indent again.
  • Keep the Status Bar in view — it tells you the language mode and warns of problems.

Disambiguation: "VS Code" (the free editor in this guide) is not "Visual Studio" (a large, separate IDE for .NET/C++), even though both are Microsoft products. Tutorials sometimes say "Visual Studio" loosely — if they show the interface from this guide, they mean VS Code.

Exercise 3.3 — Curate your setup

  1. Open the Extensions view and read the description of one extension before installing it.
  2. Install an icon theme (search "Material Icon Theme" or similar) and enable it.
  3. Disable it, notice the file icons revert, then re-enable it.
  4. Uninstall any extension you don't actually need.
  5. Write your own three-line "good habits" note and pin it somewhere you'll see it.

Glossary

Canonical terms for this guide. Definitions state what a term is, not how to use it. Each Avoid line lists synonyms that cause confusion.

Editor & Setup Terms

VS Code
Microsoft's free, lightweight code editor — the program this guide installs and uses.
Avoid: "Visual Studio", "VS" — Visual Studio is a different, much larger IDE.
User Installer
The Windows installer that sets up VS Code for your account only, without needing an administrator password. The recommended default.
Avoid: "admin installer" — that describes the System Installer, the opposite choice.
Workspace
The folder you have open in VS Code; its files show in the Explorer.
Avoid: "project file" — a workspace is a folder, not a single file.
Command Palette
The Ctrl+Shift+P search box that runs any VS Code command by name.
Avoid: "search bar" — that usually means Ctrl+F in-file search.
Extension
An add-on from the Marketplace that gives VS Code new abilities, such as Live Server or Prettier.
Avoid: "plugin", "add-on" — VS Code's own name is "extension".
Emmet
The built-in feature that expands short abbreviations (like ! or ul>li*3) into full HTML when you press Tab.
Avoid: "autocomplete", "snippet" — those are related but separate features.

HTML File Terms

Element / Tag
A building block of HTML written between angle brackets, like <p>…</p>. The opening and closing tags plus their content form an element.
Avoid: using "tag" and "element" as if fully interchangeable — a tag is one bracketed part; the element is the whole thing.
Extension (file)
The suffix after the dot in a filename, such as .html, that tells software what kind of file it is.
Avoid: confusing this with a VS Code Extension (an add-on) — same word, different meaning.
Live Server
An extension that serves your HTML and auto-refreshes the browser each time you save.
Avoid: "web host", "deploy" — Live Server runs only on your own machine for previewing.
Localhost
Your own computer acting as a web server; addresses like 127.0.0.1:5500 point back to it.
Avoid: "the internet" — a localhost page is not published or visible to anyone else.
