Working in Colab

This edition assumes Google Colab is your IDE and Google Drive is your filesystem. You will not install Python, create a virtual environment, or open a terminal until Module 5.2 — and even then only optionally. Everything runs in a browser tab.

That trade is deliberate. You skip a week of environment problems, and in exchange you inherit a different set of problems: a runtime that disconnects, a kernel that remembers things your code no longer says, and a filesystem that quietly empties itself. This section is about those.

The mental model

PieceWhat it isWhat kills it
Notebook (.ipynb)Your cells and their saved output. Lives in Drive.Nothing — it autosaves
Runtime (kernel)A throwaway Linux VM running Python. Holds every variable you have defined.90 min idle, 12 h max, "Restart runtime"
Local disk (/content)The VM's own disk. Fast. Empty at every start.Runtime ending — everything is gone
Drive (/content/drive/MyDrive)Your real Drive, mounted as a folder. Slow but permanent.Nothing — this is where data belongs

The one rule that prevents most Colab pain: anything you want tomorrow goes in Drive. Anything you want fast goes in /content. The 412,908-row file in Module 3.2 is generated straight to /content on purpose — reading it over the Drive mount is roughly ten times slower and teaches you nothing extra.

The Dataset — Sales 2026

Rodel Industrial Supply distributes pump, valve, and instrumentation parts to plants in NCR, Cebu, and Davao. Sales 2026 is six months of their order book: 646 clean order lines across 8 products and 34 active accounts, plus a handful of rows that are deliberately broken.

You use this one dataset for all 15 modules and all 6 capstones. That is the point — you stop spending attention on what the columns mean and spend it on the Python. By Phase 4 you will know this data well enough to spot a wrong answer without checking.

Why this dataset and not a sample from the internet: it is the same order book used in the From Excel to SQL track — same products, same prices, same regions. A Pump seal is ₱1,450 there and ₱1,450 here. When you write df.groupby("region") in Module 2.3, you are reproducing a pivot table you have already built by dragging fields, and later a GROUP BY you have already written in SQL. Three tools, one answer.

Generate it: make_dataset.py

Paste this into a cell prefixed with %%writefile /content/drive/MyDrive/sales2026/make_dataset.py, run the cell to save it, then run it in the next cell with !python make_dataset.py. It is deterministic — same seed, same bytes, every time — so your numbers will match every figure printed in this guide.

It writes to ./data relative to the working directory, so %cd into ROOT first. Regenerating is always safe: it overwrites, never appends.

"""make_dataset.py — generate the Sales 2026 dataset used by every exercise.

Creates three CSVs in ./data:
    products.csv    8 rows   dimension: catalogue, price, stock
    customers.csv  37 rows   dimension: account, region, segment (3 dormant)
    sales.csv     652 rows   fact: one row per order line (646 clean + 6 deliberately bad)

Deterministic: same seed, same files, every time.
    python make_dataset.py                # 646 clean order lines
    python make_dataset.py --rows 412908  # big file for the streaming exercises
"""

from __future__ import annotations

import argparse
import csv
import random
from datetime import date, timedelta
from pathlib import Path

SEED = 2026
START = date(2026, 1, 1)
END = date(2026, 6, 30)

# product_code, product, category, unit_price, stock, reorder_point
PRODUCTS = [
    ("PS-100", "Pump seal",         "Rotating equipment",  1450.00, 240,  60),
    ("BR-500", "Bearing housing",   "Rotating equipment",  6750.00,  48,  20),
    ("IM-600", "Impeller",          "Rotating equipment", 12300.00,   8,  12),
    ("VK-200", "Valve kit",         "Valves & fittings",   8900.00,  62,  25),
    ("GS-300", "Gasket set",        "Valves & fittings",    320.00, 900, 200),
    ("CV-800", "Check valve",       "Valves & fittings",   4150.00,   9,  15),
    ("FM-400", "Flow meter",        "Instrumentation",    24500.00,   5,   8),
    ("PG-700", "Pressure gauge",    "Instrumentation",     1980.00, 130,  40),
]

SEGMENTS = ["Manufacturing", "Utilities", "Marine", "Construction"]

# region -> (number of active accounts, number of clean order lines)
REGIONS = {"NCR": (18, 406), "Cebu": (10, 142), "Davao": (6, 98)}

# Accounts on the books that never placed an order in the period. They exist so
# the anti-join exercises ("which customers bought nothing?") return real rows.
DORMANT = [
    ("C-NCR-019", "NCR Industrial Account 19",   "NCR",   "Construction"),
    ("C-CEB-011", "Cebu Industrial Account 11",  "Cebu",  "Utilities"),
    ("C-DAV-007", "Davao Industrial Account 07", "Davao", "Marine"),
]

# Regional demand mix. NCR skews to rotating equipment, Cebu to valves,
# Davao is mixed — this is what makes the GROUP BY exercises interesting.
MIX = {
    "NCR":   [0.20, 0.14, 0.10, 0.12, 0.18, 0.08, 0.06, 0.12],
    "Cebu":  [0.10, 0.06, 0.04, 0.26, 0.28, 0.14, 0.04, 0.08],
    "Davao": [0.22, 0.10, 0.06, 0.14, 0.20, 0.10, 0.08, 0.10],
}

# Six deliberately broken rows. Module 2.2 logs and skips them;
# Module 2.3 drops the duplicate. Do not "fix" them in the generator.
BAD_ROWS = [
    ("PH-01412", "2026-03-11", "C-NCR-004", "PS-100",  "NCR",   ""),      # blank qty
    ("PH-01488", "2026-03-29", "C-CEB-002", "GS-300",  "Cebu",  "six"),   # qty not numeric
    ("PH-01041", "2026-01-04", "C-NCR-001", "PS-100",  "NCR",   "12"),    # duplicate order_id
    ("PH-01530", "2026-04-14", "C-DAV-003", "ZZ-999",  "Davao", "4"),     # unknown product
    ("PH-01602", "",           "C-NCR-011", "VK-200",  "NCR",   "3"),     # missing date
    ("PH-01655", "2026-05-30", "C-CEB-007", "FM-400",  "Cebu",  "-2"),    # negative qty
]


def build_customers() -> list[dict]:
    rng = random.Random(SEED)
    rows = []
    for region, (n_accounts, _) in REGIONS.items():
        prefix = {"NCR": "NCR", "Cebu": "CEB", "Davao": "DAV"}[region]
        for i in range(1, n_accounts + 1):
            rows.append({
                "customer_id": f"C-{prefix}-{i:03d}",
                "customer": f"{region} Industrial Account {i:02d}",
                "region": region,
                "segment": rng.choice(SEGMENTS),
            })
    fields = ["customer_id", "customer", "region", "segment"]
    rows += [dict(zip(fields, d)) for d in DORMANT]
    return rows


def build_sales(customers: list[dict], scale: int | None) -> list[dict]:
    rng = random.Random(SEED + 1)
    dormant = {d[0] for d in DORMANT}
    by_region: dict[str, list[str]] = {r: [] for r in REGIONS}
    for c in customers:
        if c["customer_id"] not in dormant:
            by_region[c["region"]].append(c["customer_id"])

    codes = [p[0] for p in PRODUCTS]
    span = (END - START).days

    # Scale each region's line count proportionally when --rows is given.
    base_total = sum(n for _, n in REGIONS.values())
    counts = {r: n for r, (_, n) in REGIONS.items()}
    if scale:
        counts = {r: round(n * scale / base_total) for r, n in counts.items()}

    rows, oid = [], 1041
    for region, n_lines in counts.items():
        for _ in range(n_lines):
            code = rng.choices(codes, weights=MIX[region])[0]
            price = dict((p[0], p[3]) for p in PRODUCTS)[code]
            # Cheap consumables move in bulk; capital items move in ones and twos.
            qty = rng.randint(10, 60) if price < 1000 else (
                rng.randint(3, 18) if price < 5000 else rng.randint(1, 5))
            rows.append({
                "order_id": f"PH-{oid:05d}",
                "order_date": (START + timedelta(days=rng.randint(0, span))).isoformat(),
                "customer_id": rng.choice(by_region[region]),
                "product_code": code,
                "region": region,
                "qty": str(qty),
            })
            oid += 1

    rows.sort(key=lambda r: r["order_date"])
    if not scale:  # only pollute the small teaching file
        fields = ["order_id", "order_date", "customer_id", "product_code", "region", "qty"]
        rows += [dict(zip(fields, bad)) for bad in BAD_ROWS]
    return rows


def write_csv(path: Path, rows: list[dict], fields: list[str]) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    with path.open("w", newline="", encoding="utf-8") as f:
        w = csv.DictWriter(f, fieldnames=fields)
        w.writeheader()
        w.writerows(rows)
    print(f"wrote {path}  ({len(rows)} rows)")


def main() -> None:
    ap = argparse.ArgumentParser()
    ap.add_argument("--rows", type=int, default=None,
                    help="total clean order lines (default 646)")
    ap.add_argument("--out", type=Path, default=Path("data"))
    args = ap.parse_args()

    products = [dict(zip(
        ["product_code", "product", "category", "unit_price", "stock", "reorder_point"],
        (row[0], row[1], row[2], f"{row[3]:.2f}", row[4], row[5]),
    )) for row in PRODUCTS]
    customers = build_customers()
    sales = build_sales(customers, args.rows)

    write_csv(args.out / "products.csv", products,
              ["product_code", "product", "category", "unit_price", "stock", "reorder_point"])
    write_csv(args.out / "customers.csv", customers,
              ["customer_id", "customer", "region", "segment"])
    write_csv(args.out / "sales.csv", sales,
              ["order_id", "order_date", "customer_id", "product_code", "region", "qty"])


if __name__ == "__main__":
    main()

It is also the first thing you will ever run with %%writefile rather than typing into a cell — worth noticing, because from Phase 3 onward that is how all of your real code gets written.

There is no revenue column, and that is deliberate. Revenue is qty × unit_price, and unit_price lives in a different file. Every meaningful question about this dataset therefore requires a join — in Excel that is XLOOKUP, in Pandas it is .merge(), in SQL it is JOIN … ON. Same move, three syntaxes.

What is deliberately wrong

Real order books are dirty. These six rows are appended to sales.csv on purpose so that Modules 2.1, 2.2, and 2.3 have something real to defend against. Do not fix them in the generator — fix them in your loader.

order_idProblemCaught by
PH-01412qty is emptyNumeric cast → ValueError
PH-01488qty is the word sixNumeric cast → ValueError
PH-01041Duplicate of an existing order_idOnly drop_duplicates / a uniqueness check

Five rows fail a row-level validation pass. The sixth — the duplicate — passes every field check and is only caught by a uniqueness constraint. 652 − 5 − 1 = 646. If your pipeline reports 646 clean order lines, your cleaning is correct.

The big file

646 rows fit in memory a thousand times over, which makes them useless for teaching streaming. The generator takes a --rows flag for exactly that — and it writes to /content, not Drive, on purpose:

%cd /content/drive/MyDrive/sales2026
!python make_dataset.py --rows 412908 --out /content/data_big
!ls -lh /content/data_big/sales.csv     # ~18 MB
# BIG = Path("/content/data_big") from your paths cell

Why not Drive? The Drive mount is a network filesystem. Streaming 412,908 rows through it is roughly ten times slower than reading the same file from /content, and the delay is network latency, not Python — which would completely obscure the thing Module 3.2 is trying to show you. Generate it to /content, use it, and regenerate it after a restart. It takes about four seconds.

Module 3.2 (generators) and the Final Capstone use this file. Same schema, same products, same regions — 640× the rows and no bad rows, so the only new problem is memory. Loading it with list(csv.DictReader(f)) works but is wasteful; loading it with pd.read_csv works and is fine; loading a 40-million-row version would exhaust the runtime, and that is the lesson.

def line_total(unit_price: float, qty: int = 1, *, vat: float = 0.0) -> float:

class InvalidOrderRow(Exception):
    """A sales row that cannot be trusted. Carries the offending row."""
    def __init__(self, row: dict, reason: str):
        self.row, self.reason = row, reason
        super().__init__(f"{row.get('order_id', '?')}: {reason}")

def parse_qty(row: dict) -> int:
    raw = row.get("qty", "")
    try:
        qty = int(raw)
    except (TypeError, ValueError):
        raise InvalidOrderRow(row, f"qty is not an integer: {raw!r}") from None
    if qty <= 0:
        raise InvalidOrderRow(row, f"qty must be positive, got {qty}")
    return qty

# try/except/else/finally
try:
    q = parse_qty({"order_id": "PH-01488", "qty": "six"})
except InvalidOrderRow as e:
    print("rejected:", e)      # rejected: PH-01488: qty is not an integer: 'six'
else:
    print("ok:", q)
finally:
    print("done")

def load_sales(path: str) -> tuple[list[dict], list[InvalidOrderRow]]:
    import csv
    clean, rejects, seen = [], [], set()
    with open(path, newline="", encoding="utf-8") as f:
        for row in csv.DictReader(f):
            try:
                row["qty"] = parse_qty(row)
                if not row["order_date"]:
                    raise InvalidOrderRow(row, "order_date is empty")
                if row["order_id"] in seen:
                    raise InvalidOrderRow(row, "duplicate order_id")
                seen.add(row["order_id"])
            except InvalidOrderRow as e:
                log.warning("%s", e)
                rejects.append(e)
            else:
                clean.append(row)
    log.info("clean=%d rejects=%d", len(clean), len(rejects))
    return clean, rejects

class Product:
    def __init__(self, code: str, name: str, unit_price: float,
                 stock: int, reorder_point: int):
        self.code = code
        self.name = name
        self.unit_price = unit_price
        self.stock = stock
        self.reorder_point = reorder_point

    def ship(self, qty: int) -> float:
        if qty > self.stock:
            raise ValueError(f"{self.code}: requested {qty}, only {self.stock} on hand")
        self.stock -= qty
        return round(self.unit_price * qty, 2)

    @property
    def needs_reorder(self) -> bool:
        return self.stock < self.reorder_point

    def __repr__(self) -> str:
        return f"Product({self.code!r}, stock={self.stock})"

seal = Product("PS-100", "Pump seal", 1450.00, 240, 60)
print(seal.ship(12))        # 17400.0
print(seal.stock)           # 228

import csv

def read_rows(path: Path):
    """Yield rows one at a time — constant memory regardless of file size."""
    with open(path, newline="", encoding="utf-8") as f:
        yield from csv.DictReader(f)

PRICES = {"PS-100": 1450.0, "BR-500": 6750.0, "IM-600": 12300.0, "VK-200": 8900.0,
          "GS-300": 320.0, "CV-800": 4150.0, "FM-400": 24500.0, "PG-700": 1980.0}

Chaining Generators Into a Pipeline

def only(rows, region: str):
    for r in rows:
        if r["region"] == region:
            yield r

def priced(rows):
    for r in rows:
        r["revenue"] = int(r["qty"]) * PRICES[r["product_code"]]
        yield r

pipeline = priced(only(read_rows(BIG / "sales.csv"), "NCR"))
ncr_total = sum(r["revenue"] for r in pipeline)

Nothing is read until sum asks for it, and no more than one row is ever in memory. This is what WHERE plus a streaming aggregate looks like when you write it yourself.

Decorators

Measure it two ways. %%time is the quick answer; a decorator is the reusable one, and works on functions you call from other functions:

%%time

%%time

import functools, time

def timed(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.perf_counter() - start:.3f}s")
        return result
    return wrapper

@timed
def count_rows(path: Path) -> int:
    return sum(1 for _ in read_rows(path))

print(count_rows(BIG / "sales.csv"))
# count_rows took 0.9xx s
# 412908

import csv
from pathlib import Path
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field

DATA = Path("/content/drive/MyDrive/sales2026/data")
app = FastAPI(title="Sales 2026 API")

class Product(BaseModel):
    product_code: str
    product: str
    category: str
    unit_price: float = Field(gt=0)
    stock: int = Field(ge=0)
    reorder_point: int = Field(ge=0)

class OrderIn(BaseModel):
    customer_id: str
    product_code: str
    qty: int = Field(gt=0)      # rejects the PH-01655 case at the door

CATALOG: dict[str, Product] = {}

@app.on_event("startup")
def load_catalog() -> None:
    with (DATA / "products.csv").open(newline="", encoding="utf-8") as f:
        for r in csv.DictReader(f):
            CATALOG[r["product_code"]] = Product(**r)

@app.get("/products")
def list_products(category: str | None = None) -> list[Product]:
    items = list(CATALOG.values())
    return [p for p in items if p.category == category] if category else items

@app.get("/products/{code}")
def get_product(code: str) -> Product:
    if code not in CATALOG:
        raise HTTPException(404, f"unknown product_code {code}")
    return CATALOG[code]

@app.get("/reorder")
def reorder_list() -> list[Product]:
    return [p for p in CATALOG.values() if p.stock < p.reorder_point]

@app.post("/orders", status_code=201)
def place_order(order: OrderIn) -> dict:
    product = CATALOG.get(order.product_code)
    if product is None:
        raise HTTPException(404, f"unknown product_code {order.product_code}")
    if order.qty > product.stock:
        raise HTTPException(409, f"insufficient stock: {product.stock} on hand")
    product.stock -= order.qty
    return {"ok": True, "revenue": round(product.unit_price * order.qty, 2),
            "remaining": product.stock}

import argparse
from pathlib import Path
from .loader import load_sales
from .report import revenue_by

DATA = Path("/content/drive/MyDrive/sales2026/data")

def main() -> int:
    ap = argparse.ArgumentParser(prog="sales2026")
    sub = ap.add_subparsers(dest="cmd", required=True)
    sub.add_parser("reorder")
    rev = sub.add_parser("revenue")
    rev.add_argument("--by", choices=["region", "category", "month"], default="region")
    sub.add_parser("validate")
    args = ap.parse_args()

    if args.cmd == "validate":
        clean, rejects = load_sales(DATA / "sales.csv")
        print(f"clean={len(clean)} rejects={len(rejects)}")
        return 0 if (len(clean), len(rejects)) == (646, 6) else 1
    if args.cmd == "revenue":
        for k, v in revenue_by(args.by).items():
            print(f"{k:<22} ₱{v:>15,.2f}")
    return 0

Scheduling — the honest version

Colab has no cron. A notebook runs when a browser tab is open and a human is signed in, and Google actively disconnects idle sessions. Anything that must run unattended has to leave Colab. Three routes, in increasing order of effort:

RouteHowGood forCost
GitHub ActionsPush the package to GitHub, add a workflow on a schedule: cron, commit the CSV/XLSX output back or upload as an artifactThe weekly regional report — this is the right answer for this projectFree; needs a repo and Drive credentials replaced by files in-repo
Apps ScriptA Google Apps Script trigger that reads the Drive files and mails the summaryReport distribution, not computationFree; JavaScript, not Python
A real hostAny VM or Cloud Run job, pip install the same package, real cronThe Phase 4 API, anything with uptime expectationsMoney and ops

Same package in all three. That is the point of packaging it: sales2026 revenue --by region runs identically from a Colab cell, a GitHub runner, and a server, and none of them needs the notebook.

  schedule:

        with: { name: weekly-report, path: report.txt }
