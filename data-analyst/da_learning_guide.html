Power Query is Excel's built-in ETL engine. It handles data import, transformation, and loading — all without formulas, and with a reproducible, step-by-step pipeline. 2.1.5 M Language Basics

// Each step creates a new table variable
let
    Source = Excel.Workbook(File.Contents("sales.xlsx"), null, true),
    Sheet1 = Source{[Item="Sheet1",Kind="Sheet"]}[Data],
    PromotedHeaders = Table.PromoteHeaders(Sheet1, [PromoteAllScalars=true]),
    TypedColumns = Table.TransformColumnTypes(PromotedHeaders,{
        {"OrderDate", type date},
        {"Sales", type number},
        {"Region", type text}

    FilteredRows = Table.SelectRows(TypedColumns, each [Sales] > 0),
    AddedMargin = Table.AddColumn(FilteredRows, "Margin%", 
        each [Profit] / [Sales], Percentage.Type)
in
    AddedMargin

2.2.1 The Data Model

  • What is a data model: multiple tables connected by relationships
  • Star schema vs. snowflake schema
  • Fact tables vs. dimension tables

Star Schema (standard pattern)

                  dim_Product
                      |
dim_Date ── fact_Sales ── dim_Customer
                      |
                  dim_Region
  • Fact table: transactional data — Sales, Orders, Payments
  • Dimension tables: descriptive context — Products, Customers, Dates, Regions

2.2.2 Relationships

  • One-to-many (most common): one Product → many Sales rows
  • Cross-filter direction: Single vs. Both
  • Creating relationships in Diagram View
  • Active vs. inactive relationships
  • Never use VLOOKUP between tables once you're in the data model — use relationships instead

2.2.3 DAX — Data Analysis Expressions

DAX Concepts - Calculated Columns: row-by-row computation, stored in the model - Measures: aggregation computed at query time, respects filter context - Filter Context: the active filters from slicers, pivot rows/columns - Row Context: the current row being evaluated (in calculated columns and iterators)

Common mistake: Using a Calculated Column when you need a Measure. A calculated column computes once per row at refresh and is fixed — it ignores slicers entirely. A Measure re-evaluates on every query in the current filter context. Using a calculated column for KPIs produces static, un-filterable numbers that look correct until a slicer is applied.

DAX Syntax Structure

Measure Name = FUNCTION(arguments)

Basic Aggregation Measures

Total Sales = SUM(fact_Sales[Revenue])
Total Orders = COUNTROWS(fact_Sales)
Avg Order Value = AVERAGE(fact_Sales[Revenue])
Unique Customers = DISTINCTCOUNT(fact_Sales[CustomerID])
Max Sale = MAX(fact_Sales[Revenue])

Logical Functions

Profitable Orders = 
    CALCULATE(
        COUNTROWS(fact_Sales),
        fact_Sales[Profit] > 0
    )

CALCULATE — the most important DAX function

-- CALCULATE modifies filter context
Sales in East = CALCULATE([Total Sales], dim_Region[Region] = "East")

Sales Excluding Furniture = 
    CALCULATE([Total Sales], dim_Product[Category] <> "Furniture")

-- ALL() removes all filters
Sales All Time = CALCULATE([Total Sales], ALL(dim_Date))

Time Intelligence

-- Requires a proper Date dimension table with contiguous dates
Sales LY = CALCULATE([Total Sales], SAMEPERIODLASTYEAR(dim_Date[Date]))

Sales YTD = TOTALYTD([Total Sales], dim_Date[Date])

Sales MTD = TOTALMTD([Total Sales], dim_Date[Date])

YoY Growth % = 
    DIVIDE([Total Sales] - [Sales LY], [Sales LY], BLANK())

Rolling 3M Sales = 
    CALCULATE([Total Sales], DATESINPERIOD(dim_Date[Date], LASTDATE(dim_Date[Date]), -3, MONTH))

Iterator Functions (X functions)

-- SUMX evaluates an expression per row, then sums
Total Revenue = SUMX(fact_Sales, fact_Sales[Quantity] * fact_Sales[UnitPrice])

-- AVERAGEX
Avg Profit Per Order = AVERAGEX(fact_Sales, fact_Sales[Profit])

-- RANKX
Product Sales Rank = RANKX(ALL(dim_Product), [Total Sales],, DESC, Dense)

Filter Functions

-- FILTER returns a table
Top 10 Products = 
    CALCULATE([Total Sales], TOPN(10, dim_Product, [Total Sales], DESC))

-- RELATED pulls from related dimension
Category Sales = CALCULATE([Total Sales], RELATED(dim_Product[Category]))

-- VALUES returns distinct values in current filter context
Categories In View = CONCATENATEX(VALUES(dim_Product[Category]), dim_Product[Category], ", ")

2.2.4 Date Dimension Table

A proper date dimension is mandatory for time intelligence.

-- Create in Power Query (M)
let
    StartDate = #date(2020, 1, 1),
    EndDate = #date(2025, 12, 31),
    DateList = List.Dates(StartDate, Duration.Days(EndDate - StartDate) + 1, #duration(1,0,0,0)),
    DateTable = Table.FromList(DateList, Splitter.SplitByNothing(), {"Date"}),
    TypedDate = Table.TransformColumnTypes(DateTable, {{"Date", type date}}),
    AddYear    = Table.AddColumn(TypedDate, "Year", each Date.Year([Date]), Int64.Type),
    AddMonth   = Table.AddColumn(AddYear, "MonthNo", each Date.Month([Date]), Int64.Type),
    AddMonthName = Table.AddColumn(AddMonth, "MonthName", each Date.ToText([Date], "MMMM"), type text),
    AddQtr     = Table.AddColumn(AddMonthName, "Quarter", each "Q" & Text.From(Date.QuarterOfYear([Date])), type text),
    AddWkNo    = Table.AddColumn(AddQtr, "WeekNo", each Date.WeekOfYear([Date]), Int64.Type),
    AddDayName = Table.AddColumn(AddWkNo, "DayName", each Date.ToText([Date], "dddd"), type text),
    AddIsWeekend = Table.AddColumn(AddDayName, "IsWeekend", 
        each Date.DayOfWeek([Date], Day.Monday) >= 5, type logical)
in
    AddIsWeekend

  • Correlation: produces a full correlation matrix across multiple columns
  • Regression: linear regression output (coefficients, R², F-stat, residuals) — good for quick sanity checks
  • t-Test (two-sample): tests if two groups have different means
  • ANOVA: Single Factor: tests if 3+ groups have different means
  • Moving Average: calculates rolling averages for time series smoothing
  • Sampling: draws a random or periodic sample from a data range

ToolPak vs. formulas: ToolPak outputs are static — they don't recalculate when data changes. Use it for one-off analysis; use formulas (=STDEV, =CORREL, =FORECAST) when you need live results.

p-value Probability of results given null hypothesis is true p < 0.05 = statistically significant
Confidence Interval Range likely to contain true population parameter 95% CI: "we're 95% confident the mean falls here"
Effect Size Magnitude of difference (Cohen's d) Statistical significance ≠ practical importance

4.2.1 Window Functions

Window functions are the single most powerful tool in analytical SQL. They compute aggregates over a "window" of rows without collapsing the result set.

-- Syntax
function() OVER (
    PARTITION BY column    -- reset per group (optional)
    ORDER BY column        -- order within window (required for running calcs)
    ROWS/RANGE BETWEEN ... -- frame (optional)
)

-- ROW_NUMBER, RANK, DENSE_RANK
SELECT
    order_id,
    customer_id,
    sales,
    ROW_NUMBER()  OVER (PARTITION BY customer_id ORDER BY sales DESC) AS row_num,
    RANK()        OVER (PARTITION BY customer_id ORDER BY sales DESC) AS rnk,
    DENSE_RANK()  OVER (PARTITION BY customer_id ORDER BY sales DESC) AS dense_rnk
FROM orders;

-- Running totals and moving averages
SELECT
    order_date,
    sales,
    SUM(sales)  OVER (ORDER BY order_date) AS running_total,
    AVG(sales)  OVER (ORDER BY order_date
                      ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) AS rolling_7d_avg
FROM orders;

-- LAG / LEAD: compare to previous or next row
SELECT
    order_date,
    sales,
    LAG(sales, 1, 0)  OVER (ORDER BY order_date) AS prev_sales,
    sales - LAG(sales, 1, 0) OVER (ORDER BY order_date) AS sales_change,
    LEAD(sales, 1, 0) OVER (ORDER BY order_date) AS next_sales
FROM (
    SELECT DATE_TRUNC('month', order_date) AS order_date,
           SUM(sales) AS sales
    FROM orders
    GROUP BY 1
) monthly;

-- FIRST_VALUE / LAST_VALUE / NTH_VALUE
SELECT
    customer_id,
    order_id,
    order_date,
    sales,
    FIRST_VALUE(order_date) OVER (PARTITION BY customer_id ORDER BY order_date) AS first_order,
    LAST_VALUE(sales)       OVER (PARTITION BY customer_id ORDER BY order_date
                                  ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS last_sale
FROM orders;

-- NTILE: divide into quartiles
SELECT
    customer_id,
    SUM(sales) AS total_sales,
    NTILE(4) OVER (ORDER BY SUM(sales) DESC) AS sales_quartile
FROM orders
GROUP BY customer_id;

-- PERCENT_RANK and CUME_DIST
SELECT
    product_id,
    SUM(sales)                                 AS product_sales,
    PERCENT_RANK() OVER (ORDER BY SUM(sales))  AS pct_rank,
    CUME_DIST()    OVER (ORDER BY SUM(sales))  AS cumulative_dist
FROM orders
GROUP BY product_id;

    SELECT
        PERCENTILE_CONT(0.25) WITHIN GROUP (ORDER BY sales) AS q1,

    FROM orders
),

    FROM stats

FROM orders o, bounds b
WHERE o.sales < b.lower_bound OR o.sales > b.upper_bound;

CREATE INDEX idx_orders_date        ON orders(order_date);

-- Composite index (useful when you always filter on both columns together)
CREATE INDEX idx_orders_region_date ON orders(region, order_date);

-- Unique index (also enforces uniqueness)
CREATE UNIQUE INDEX idx_orders_order_id ON orders(order_id);

-- Check if a query uses an index
EXPLAIN ANALYZE
SELECT * FROM orders WHERE customer_id = 'CUST-001';
-- Look for "Index Scan" vs "Seq Scan" in the output

-- Drop an index
DROP INDEX IF EXISTS idx_orders_customer_id;

Index guidelines for analysts: Index every foreign key column, every column used in WHERE filters on large tables, and every column used in frequent ORDER BY. Don't over-index — each index slows INSERT/UPDATE. Most query tuning starts with EXPLAIN ANALYZE, not guessing.

Glossary

Canonical terms for this guide. Definitions state what a term is, not how to use it. Each Avoid line lists synonyms that cause confusion.

Data Foundations

Grain
The level of detail at which a fact table records one row — per order, per order-line item, per day. The grain must be defined before building any data model; the wrong grain makes every aggregate built on the table incorrect.
Avoid: "granularity," "row level" — grain is the precise term for the unit of measurement in a fact table.
Structured Data
Data organized in a fixed schema with named columns and consistent types — spreadsheets and relational databases. Structured data can still be dirty (nulls, typos, wrong types).
Avoid: "clean data" (structured data can be unclean); "tabular data" (less standard in formal data contexts).
Descriptive Analytics
Analysis that summarizes what happened over a historical period — counts, sums, averages, trends. Most dashboard and reporting work is descriptive analytics.
Avoid: "reporting" (reporting is an output format, not an analytics type); conflating with diagnostic or predictive analytics.
Correlation
A statistical measure of how strongly two variables move together. Correlation does not imply causation — a shared cause or coincidence can produce high correlation with no direct link between the variables.
Avoid: using "correlation" to imply causation — this is the single most common analytical error in business reporting.
Outlier
A data point that falls far outside the typical range of a variable. Outliers may be data quality errors (fix them) or genuine extreme events (retain them and flag them). The appropriate response depends on the cause, not the value alone.
Avoid: "bad data" — outliers are not automatically wrong; automatically removing them without investigation is an analysis error.

Excel & ETL

ETL (Extract, Transform, Load)
The three-step process of pulling data from a source, cleaning and reshaping it, and loading it into a destination. In Excel, Power Query is the ETL engine; in data engineering, dedicated tools (dbt, Airflow) handle ETL at scale.
Avoid: "data prep," "data wrangling" (informal); "ELT" (a separate pattern where data is loaded first and transformed in the destination — used in cloud warehouses).
Power Query
Excel's built-in ETL engine — connects to external sources, records every transformation as a named, reproducible step, and loads clean data to the workbook or data model. The same engine powers Power BI's data transformation layer.
Avoid: "Get & Transform" (the deprecated UI label no longer used in current Excel versions).
Measure
A DAX calculation that is evaluated at query time in the current filter context — it re-computes every time a slicer, pivot row, or CALCULATE modifies the filter. Measures are the standard way to define KPIs in Power Pivot and Power BI.
Avoid: "calculated field" (the Excel pivot table term); "calculated column" — a calculated column is stored per row at refresh and does not respond to the current filter context.
Star Schema
A data model with one central fact table (transactions) connected to multiple dimension tables (Products, Customers, Dates, Regions) via one-to-many relationships. The standard pattern for Power Pivot and Power BI models.
Avoid: "data model" alone (too vague); "snowflake schema" (snowflakes normalize dimension tables further — useful for storage but slower for interactive analysis).
Filter Context
The set of active filters — from slicers, pivot rows and columns, and CALCULATE — that determines which rows a DAX measure evaluates. Misunderstanding filter context is the root cause of most DAX calculation bugs.
Avoid: confusing with Row Context — row context applies only inside calculated columns and DAX iterator functions (SUMX, AVERAGEX); filter context applies to measures.

Python & Analysis

DataFrame
Pandas' primary two-dimensional data structure — a labeled table of rows and columns that can hold mixed data types (strings, numbers, dates). All tabular data work in Python flows through DataFrames.
Avoid: "table," "matrix" — a NumPy matrix is numeric-only; a DataFrame holds mixed types and has labeled axes.
EDA (Exploratory Data Analysis)
An open-ended process of understanding a new dataset — distributions, missing values, outliers, correlations — before building any model or visualization. EDA reveals what the data contains, not what you expect it to contain.
Avoid: "data exploration," "preliminary analysis" — EDA is a specific, structured approach (coined by Tukey) with established techniques, not an informal look at the data.
NaN (Not a Number)
Pandas' representation of a missing value. NaN propagates silently through calculations — 5 + NaN = NaN — so every missing value must be handled explicitly before analysis.
Avoid: "null," "blank," "empty" — those are SQL and Excel terms; in Pandas the missing value representation is NaN, and the detection functions are isna() / notna().
Overfitting
When a model fits the training data too closely — memorizing noise instead of learning patterns — and fails to generalize to new data. Detected as a high training score paired with a significantly lower test score.
Avoid: "the model is too accurate" — high accuracy on training data is a warning sign, not a success; the test score is the true measure.

SQL

JOIN
A SQL operation that combines rows from two or more tables based on a matching key column. The most common types are INNER JOIN (only matching rows), LEFT JOIN (all rows from the left table, matched or not), and FULL OUTER JOIN.
Avoid: "merge" — merge is the Pandas and Power Query term for the same operation; in SQL the operation is always JOIN.
Window Function
A SQL function that computes a result across a set of rows related to the current row — without collapsing them into a group. Unlike GROUP BY, the original rows are preserved. Examples: SUM OVER, LAG, RANK, NTILE.
Avoid: "aggregate function" — standard aggregates with GROUP BY collapse rows into one per group; window functions keep all rows and add a computed column alongside them.
CTE (Common Table Expression)
A named temporary result set defined with WITH that makes a complex query readable by breaking it into named, sequential steps. A CTE can be referenced multiple times within the same statement.
Avoid: "subquery" — a subquery is embedded inline inside another query; a CTE is named, defined at the top, and is reusable — the two have different readability and debugging profiles.
NULL
A SQL marker meaning "no value recorded" — not zero, not empty string, but the absence of a value. Any comparison involving NULL (including = NULL) returns NULL, not true or false. Use IS NULL and IS NOT NULL instead.
Avoid: "zero," "empty," "blank" — NULL is a distinct third logical state; treating it as zero or empty produces silent calculation errors.
