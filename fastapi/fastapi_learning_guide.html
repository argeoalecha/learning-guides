Module 1.1 — FastAPI Basics: Your First Endpoint

Level: Beginner · Prereqs: Python functions and pip · Time: ~2h
Skip-check (test-out): Run a FastAPI app with two GET routes, navigate to /docs, and explain what ASGI means in one sentence.
Skip if: You have already built and run a FastAPI app locally and are comfortable with the /docs Swagger UI.
Unlocks: Module 1.2

What FastAPI is and why it is fast

FastAPI is a Python web framework built on Starlette (an ASGI toolkit) and Pydantic. It generates OpenAPI documentation automatically from your Python code — no separate spec file to maintain. The "fast" in the name means two things: runtime speed (Starlette's async request handling benchmarks among the fastest Python frameworks) and developer speed (full endpoint definition in one decorated function). Without an ASGI server like Uvicorn, FastAPI cannot serve requests — the framework defines routes, Uvicorn runs them.

pip install fastapi uvicorn[standard]

Your first app

from fastapi import FastAPI

app = FastAPI(
    title="ShopPH API",
    description="Philippine e-commerce platform API",
    version="1.0.0"
)

@app.get("/")
async def root() -> dict:
    return {"message": "Welcome to ShopPH API", "docs": "/docs"}

@app.get("/health")
async def health_check() -> dict:
    return {"status": "ok", "service": "shopph-api"}

Running and exploring the docs

uvicorn main:app --reload

Open http://localhost:8000/docs for the Swagger UI — every route you define appears here automatically with a try-it-out button. /redoc gives an alternative documentation view. /openapi.json returns the raw OpenAPI schema both UIs consume. The --reload flag restarts the server on every file save during development.

Sync vs. async handlers — when it matters

Define route handlers as async def when the function calls an async library (an async database driver, httpx). Define them as regular def for CPU-bound work or when using a blocking library — FastAPI runs blocking def handlers in a thread pool automatically, keeping the event loop free.

Common mistake: Adding async def to a handler that calls a synchronous, blocking function (like a standard SQLAlchemy query with no await) does not make it non-blocking — it blocks the entire event loop for every request. If your database driver is synchronous, use regular def handlers and let FastAPI run them in the thread pool.

Module 1.2 — Path, Query & Body Parameters

Level: Beginner · Prereqs: Module 1.1 · Time: ~3h
Skip-check (test-out): Define a GET endpoint with a required path parameter (ge=1), two optional query parameters with constraints, and explain how FastAPI distinguishes path, query, and body parameters.
Skip if: You can use Path(), Query(), and Body() with validation constraints and have tested them in a working endpoint.
Unlocks: Module 1.3

Path parameters — required, part of the URL

A path parameter is declared in the route path as {name} and matched by a function argument of the same name. FastAPI validates the type automatically before calling your function — sending /products/abc to a route declared with product_id: int returns a 422 immediately, never reaching your handler. This prevents type errors from ever entering your business logic.

from fastapi import FastAPI, Path, Query
from typing import Optional

app = FastAPI()

@app.get("/products/{product_id}")
async def get_product(
    product_id: int = Path(ge=1, description="Unique product ID"),
    include_reviews: bool = Query(False, description="Include reviews in response")
) -> dict:
    return {"product_id": product_id, "include_reviews": include_reviews}

Query parameters — optional, after the ?

Any function argument not present in the path template becomes a query parameter. A default value makes it optional; no default makes it required. Optional[str] = None explicitly declares a nullable optional — the Optional annotation documents intent and makes the OpenAPI spec show the field as non-required.

@app.get("/products")
async def list_products(
    category: Optional[str] = None,
    min_price: Optional[float] = Query(None, ge=0, description="Minimum price in PHP"),
    max_price: Optional[float] = Query(None, ge=0, description="Maximum price in PHP"),
    page: int = Query(1, ge=1, description="Page number"),
    size: int = Query(20, ge=1, le=100, description="Items per page")
) -> dict:
    return {
        "category": category,
        "price_range": [min_price, max_price],
        "pagination": {"page": page, "size": size}
    }

Request body — JSON payload from the client

A Pydantic model as a function parameter tells FastAPI to parse the request body as JSON and validate it through the model. The body is completely separate from the URL — mixing them up is the most common beginner mistake when moving from Flask to FastAPI. FastAPI infers: if it is in the path, it is a path parameter; if it is a Pydantic model, it is the body; everything else is a query parameter.

from pydantic import BaseModel, Field

class CreateProductBody(BaseModel):
    name: str = Field(min_length=1, max_length=200)
    price: float = Field(gt=0, description="Price in PHP")
    category: str
    stock: int = Field(ge=0, default=0)
    description: Optional[str] = None

@app.post("/products")
async def create_product(product: CreateProductBody) -> dict:
    return {"received": product.model_dump(), "status": "created"}

Module 1.3 — Pydantic Request & Response Schemas

Level: Beginner–Intermediate · Prereqs: Module 1.2 · Time: ~3h
Skip-check (test-out): Define separate Create, Update, and Response Pydantic models for a product, explain why they are separate, and use response_model to strip an internal field from the output.
Skip if: You use separate request/response schemas, understand response_model filtering, and know what model_config from_attributes=True does.
Unlocks: Module 1.4

Separate schemas for Create, Update, and Response

Using a single model for all three operations is a common trap. The create request has no id (the database assigns it); the update request makes most fields optional; the response includes server-generated fields like created_at. One model forces the client to send fields it should not control, or exposes internal fields it should not see.

from fastapi import FastAPI
from pydantic import BaseModel, Field
from datetime import datetime
from typing import Optional
from enum import Enum

class CategoryEnum(str, Enum):
    electronics = "electronics"
    clothing = "clothing"
    food = "food"
    furniture = "furniture"

class ProductCreate(BaseModel):
    name: str = Field(min_length=1, max_length=200)
    description: Optional[str] = None
    price: float = Field(gt=0, description="Price in PHP")
    category: CategoryEnum
    stock: int = Field(ge=0, default=0)
    cost_price: float = Field(gt=0, description="Internal cost — never exposed in response")

class ProductUpdate(BaseModel):
    name: Optional[str] = Field(None, min_length=1, max_length=200)
    description: Optional[str] = None
    price: Optional[float] = Field(None, gt=0)
    stock: Optional[int] = Field(None, ge=0)

class ProductResponse(BaseModel):
    id: int
    name: str
    price: float
    category: CategoryEnum
    stock: int
    is_active: bool
    created_at: datetime
    model_config = {"from_attributes": True}

response_model — filtering the output

response_model on a route tells FastAPI to pass the return value through the named model before serializing it to JSON. Fields not declared on the response model are silently dropped. This is the primary mechanism for preventing data leaks — cost_price and hashed_password never reach the client if they are absent from the response schema.

Common mistake: response_model shapes the output — it does NOT protect the route from unauthorized access. A route with response_model=ProductResponse still returns data to any unauthenticated caller. Never confuse response shaping with authorization — those are two separate concerns handled by different mechanisms.

app = FastAPI()

@app.post("/products", response_model=ProductResponse, status_code=201)
async def create_product(product: ProductCreate) -> ProductResponse:
    return ProductResponse(
        id=1,
        name=product.name,
        price=product.price,
        category=product.category,
        stock=product.stock,
        is_active=True,
        created_at=datetime.now()
    )
    # cost_price is on ProductCreate but NOT on ProductResponse
    # FastAPI drops it automatically — it never appears in the JSON response

from_attributes — ORM row compatibility

model_config = {"from_attributes": True} lets Pydantic construct the model from any object that has matching attributes, not just dicts — including SQLAlchemy ORM rows. Set this on response models (which receive ORM objects from the database layer); request models only ever receive dicts from JSON bodies and do not need it.

APIRouter — organizing routes into files

Putting all routes in main.py becomes unmanageable past about 15 endpoints. APIRouter lets you define routes in separate modules and register them with a shared prefix and tag. The tags drive the grouping in /docs, making the API self-documenting for both developers and API consumers. Missing a prefix is the most common mistake — a router without one adds routes to the root namespace, silently colliding with other routers.

# routers/products.py
from fastapi import APIRouter
from typing import List
from datetime import datetime
from schemas.product import ProductCreate, ProductResponse, CategoryEnum

router = APIRouter(prefix="/products", tags=["Products"])

@router.get("/", response_model=List[ProductResponse])
async def list_products() -> List[ProductResponse]:
    return []

@router.get("/{product_id}", response_model=ProductResponse)
async def get_product(product_id: int) -> ProductResponse:
    return ProductResponse(
        id=product_id, name="Sample", price=299.0,
        category=CategoryEnum.electronics, stock=10,
        is_active=True, created_at=datetime.now()
    )

@router.post("/", response_model=ProductResponse, status_code=201)
async def create_product(product: ProductCreate) -> ProductResponse:
    return ProductResponse(
        id=1, name=product.name, price=product.price,
        category=product.category, stock=product.stock,
        is_active=True, created_at=datetime.now()
    )

# main.py
from fastapi import FastAPI
from routers import products, orders, users

app = FastAPI(title="ShopPH API", version="1.0.0")

app.include_router(products.router)
app.include_router(orders.router)
app.include_router(users.router)

@app.get("/health", tags=["System"])
async def health_check() -> dict:
    return {"status": "ok"}

shopph/
├── main.py
├── database.py
├── auth.py
├── dependencies.py
├── routers/
│   ├── __init__.py
│   ├── products.py
│   ├── orders.py
│   └── users.py
├── schemas/
│   ├── __init__.py
│   ├── product.py
│   ├── order.py
│   └── user.py
├── models/
│   ├── __init__.py
│   ├── product.py   ← SQLAlchemy ORM models
│   ├── order.py
│   └── user.py
├── crud/
│   ├── __init__.py
│   ├── product.py   ← database logic, no HTTP concerns
│   └── user.py
└── requirements.txt

Separating SQLAlchemy ORM models (models/) from Pydantic schemas (schemas/) avoids circular imports and keeps HTTP validation out of the database layer. The crud/ layer ensures router functions stay thin — they call a CRUD function and return the result. Business logic belongs in crud/, not in the router.

SQLAlchemy setup: engine, session, Base

The three key objects are the engine (the connection to the database file), the session factory (creates database sessions), and Base (the parent class all ORM models inherit from, used to create tables). Calling Base.metadata.create_all(engine) creates every table whose ORM model inherits from Base — run this once at startup.

# database.py
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker, DeclarativeBase

DATABASE_URL = "sqlite:///./shopph.db"
engine = create_engine(DATABASE_URL, connect_args={"check_same_thread": False})
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)

class Base(DeclarativeBase):
    pass

def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

Defining ORM models

# models/product.py
from sqlalchemy import Column, Integer, String, Float, Boolean, DateTime
from database import Base
from datetime import datetime

class Product(Base):
    __tablename__ = "products"

    id = Column(Integer, primary_key=True, index=True)
    name = Column(String, nullable=False, index=True)
    description = Column(String, nullable=True)
    price = Column(Float, nullable=False)
    category = Column(String, nullable=False)
    stock = Column(Integer, default=0)
    is_active = Column(Boolean, default=True)
    created_at = Column(DateTime, default=datetime.utcnow)

Creating tables and wiring get_db

# main.py
from fastapi import FastAPI
from database import engine, Base
import models.product  # import so Base sees the model before create_all

app = FastAPI(title="ShopPH API")

Base.metadata.create_all(bind=engine)  # creates products table on startup

# Install SQLAlchemy:  pip install sqlalchemy

The get_db generator yields a session and closes it in the finally block — ensuring the session is always returned to the pool, even if the request handler raises an exception. Forgetting the finally block leaks database connections under any error condition.

Module 2.2 — CRUD Operations

The CRUD layer — database logic separate from HTTP logic

CRUD functions live in crud/ and receive a Session — they have no knowledge of HTTP, request bodies, or status codes. Router functions call CRUD functions and translate the result to an HTTP response. This separation means you can test database logic without running the web server, and change the HTTP layer without touching database queries.

# crud/product.py
from sqlalchemy.orm import Session
from models.product import Product
from schemas.product import ProductCreate, ProductUpdate
from typing import List, Optional

def get_product(db: Session, product_id: int) -> Optional[Product]:
    return db.query(Product).filter(
        Product.id == product_id,
        Product.is_active == True
    ).first()

def get_products(
    db: Session,
    skip: int = 0,
    limit: int = 20,
    category: Optional[str] = None
) -> List[Product]:
    query = db.query(Product).filter(Product.is_active == True)
    if category:
        query = query.filter(Product.category == category)
    return query.offset(skip).limit(limit).all()

def create_product(db: Session, product: ProductCreate) -> Product:
    data = product.model_dump(exclude={"cost_price"})
    db_product = Product(**data)
    db.add(db_product)
    db.commit()
    db.refresh(db_product)
    return db_product

def update_product(
    db: Session, product_id: int, product: ProductUpdate
) -> Optional[Product]:
    db_product = get_product(db, product_id)
    if not db_product:
        return None
    for field, value in product.model_dump(exclude_none=True).items():
        setattr(db_product, field, value)
    db.commit()
    db.refresh(db_product)
    return db_product

def soft_delete_product(db: Session, product_id: int) -> bool:
    db_product = get_product(db, product_id)
    if not db_product:
        return False
    db_product.is_active = False
    db.commit()
    return True

Wiring CRUD to router endpoints

# routers/products.py
from fastapi import APIRouter, Depends, HTTPException
from sqlalchemy.orm import Session
from database import get_db
from crud import product as crud_product
from schemas.product import ProductCreate, ProductUpdate, ProductResponse
from typing import List, Optional

router = APIRouter(prefix="/products", tags=["Products"])

@router.get("/", response_model=List[ProductResponse])
def list_products(
    category: Optional[str] = None,
    skip: int = 0,
    limit: int = 20,

Password hashing with bcrypt

Never store plain-text passwords. passlib wraps bcrypt, which is deliberately slow to compute — it makes brute-force attacks against a stolen password hash database impractical. Always hash on registration and compare hashes on login; never decrypt a stored hash.

# auth.py
from datetime import datetime, timedelta
from typing import Optional
from jose import JWTError, jwt
from passlib.context import CryptContext
from pydantic import BaseModel

SECRET_KEY = "change-this-to-a-random-64-char-secret-in-production"
ALGORITHM = "HS256"
ACCESS_TOKEN_EXPIRE_MINUTES = 30

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

class TokenData(BaseModel):
    email: Optional[str] = None

def verify_password(plain: str, hashed: str) -> bool:
    return pwd_context.verify(plain, hashed)

def hash_password(password: str) -> str:
    return pwd_context.hash(password)

def create_access_token(data: dict, expires_delta: Optional[timedelta] = None) -> str:
    payload = data.copy()
    expire = datetime.utcnow() + (expires_delta or timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES))
    payload.update({"exp": expire})
    return jwt.encode(payload, SECRET_KEY, algorithm=ALGORITHM)

def decode_access_token(token: str) -> Optional[TokenData]:
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        email: Optional[str] = payload.get("sub")
        if not email:
            return None
        return TokenData(email=email)
    except JWTError:
        return None

Register and login endpoints

OAuth2PasswordRequestForm is a built-in FastAPI form dependency that reads username and password from an HTML form body (not JSON). FastAPI's Swagger UI renders the /auth/token endpoint with an "Authorize" button that uses this form format automatically.

# routers/auth.py
from fastapi import APIRouter, Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer, OAuth2PasswordRequestForm
from sqlalchemy.orm import Session
from database import get_db
from auth import verify_password, hash_password, create_access_token
from crud.user import get_user_by_email, create_user
from schemas.user import UserCreate, UserResponse, Token

router = APIRouter(prefix="/auth", tags=["Authentication"])
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/auth/token")

@router.post("/register", response_model=UserResponse, status_code=201)
def register(user: UserCreate, db: Session = Depends(get_db)) -> UserResponse:
    if get_user_by_email(db, user.email):
        raise HTTPException(status_code=400, detail="Email already registered")
    return create_user(db, email=user.email, hashed_password=hash_password(user.password))

@router.post("/token", response_model=Token)
def login(form: OAuth2PasswordRequestForm = Depends(), db: Session = Depends(get_db)) -> Token:
    user = get_user_by_email(db, form.username)
    if not user or not verify_password(form.password, user.hashed_password):
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Incorrect email or password",
            headers={"WWW-Authenticate": "Bearer"}
        )
    token = create_access_token(data={"sub": user.email})
    return Token(access_token=token, token_type="bearer")

from fastapi import Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer

from database import get_db

def get_current_user(
    token: str = Depends(oauth2_scheme),
    db: Session = Depends(get_db)
) -> User:
    token_data = decode_access_token(token)
    if not token_data:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Could not validate credentials",
            headers={"WWW-Authenticate": "Bearer"}
        )
    user = get_user_by_email(db, token_data.email)
    if not user:
        raise HTTPException(status_code=401, detail="User not found")
    return user

What Depends() does

Depends(fn) tells FastAPI to call fn before calling your route handler, and inject the return value as the parameter. If the dependency itself has parameters, FastAPI resolves those too — dependencies compose. This is how get_db and get_current_user work: they are just functions that FastAPI calls and whose return value it passes into the route.

Class-based dependencies — reusable parameter groups

# dependencies.py (additions)

Chaining dependencies

from fastapi import Depends, HTTPException
from models.user import User
from dependencies import get_current_user

def get_active_user(current_user: User = Depends(get_current_user)) -> User:
    if not current_user.is_active:
        raise HTTPException(status_code=400, detail="Inactive user account")
    return current_user

def get_admin_user(current_user: User = Depends(get_active_user)) -> User:
    if not current_user.is_admin:
        raise HTTPException(status_code=403, detail="Admin access required")
    return current_user

Chaining runs in order — get_admin_user only runs after get_active_user passes. This builds a validation pipeline where each layer adds one guard, keeping each function focused and testable independently.

BackgroundTasks — fire-and-forget after response

BackgroundTasks lets you enqueue a function to run after the HTTP response has been sent. The client gets its response immediately — the background function runs in the same process after. This is the right tool for lightweight post-response work like sending a confirmation email or writing an audit log. It is not a job queue — if the server process dies, the task is lost.

import logging

from sqlalchemy.orm import Session
from database import get_db
from dependencies import get_active_user
from models.user import User
from schemas.order import OrderCreate, OrderResponse
from crud import order as crud_order

logger = logging.getLogger(__name__)

def send_order_confirmation(order_id: int, customer_email: str) -> None:
    logger.info("Sending order confirmation for order %d to %s", order_id, customer_email)
    # In production: call SendGrid, Mailchimp, or your SMTP service here.
    logger.info("Confirmation sent to %s", customer_email)

@router.post("/", response_model=OrderResponse, status_code=201)
def create_order(
    order: OrderCreate,
    background_tasks: BackgroundTasks,
    db: Session = Depends(get_db),
    current_user: User = Depends(get_active_user)
) -> OrderResponse:
    db_order = crud_order.create_order(db, order, user_id=current_user.id)
    background_tasks.add_task(
        send_order_confirmation,
        order_id=db_order.id,
        customer_email=current_user.email
    )
    return db_order

Async HTTP calls with httpx

When your route needs to call an external API (a payment gateway, a shipping provider), use httpx.AsyncClient for non-blocking HTTP. A synchronous requests.get() call inside an async def handler blocks the event loop for every concurrent request. Use async with httpx.AsyncClient() as client: and await client.get() instead.

import httpx
from fastapi import APIRouter

router = APIRouter(prefix="/shipping", tags=["Shipping"])

@router.get("/rates/{order_id}")
async def get_shipping_rates(order_id: int) -> dict:
    async with httpx.AsyncClient() as client:
        response = await client.get(
            f"https://api.lalamove.com/v3/quotations",
            headers={"Authorization": "Bearer YOUR_KEY"},
            timeout=5.0
        )
        response.raise_for_status()
        return response.json()

CORS — allowing a frontend to call the API

Browsers block cross-origin requests by default. CORSMiddleware adds the HTTP headers that tell the browser the API permits calls from specific origins. Using allow_origins=["*"] permits every origin — acceptable during local development but never in production where user credentials are involved, because it allows any website to make authenticated requests on behalf of your users.

from fastapi import FastAPI

    CORSMiddleware,
    allow_origins=["http://localhost:3000", "https://shopph.ph"],
    allow_credentials=True,
    allow_methods=["GET", "POST", "PUT", "DELETE"],
    allow_headers=["Authorization", "Content-Type"]
)

Custom middleware — timing and logging

import time
import logging
from fastapi import Request
from fastapi.responses import Response

logger = logging.getLogger("shopph")

@app.middleware("http")
async def log_requests(request: Request, call_next) -> Response:
    start = time.perf_counter()
    response = await call_next(request)
    duration_ms = (time.perf_counter() - start) * 1000
    logger.info(
        "%s %s %d %.1fms",
        request.method, request.url.path,
        response.status_code, duration_ms
    )
    return response

Custom exception handlers

Raising HTTPException is correct for expected client errors (404, 401, 403). For domain exceptions — errors that belong to your business logic — define a custom exception class and register a handler. This keeps HTTP status codes out of your CRUD layer: CRUD raises ProductNotFoundError, the handler maps it to a 404.

from fastapi import Request, status
from fastapi.responses import JSONResponse

class ProductNotFoundError(Exception):
    def __init__(self, product_id: int):
        self.product_id = product_id

class InsufficientStockError(Exception):
    def __init__(self, product_id: int, available: int, requested: int):
        self.product_id = product_id
        self.available = available
        self.requested = requested

@app.exception_handler(ProductNotFoundError)
async def product_not_found_handler(request: Request, exc: ProductNotFoundError) -> JSONResponse:
    return JSONResponse(
        status_code=status.HTTP_404_NOT_FOUND,
        content={"error": "product_not_found", "product_id": exc.product_id}
    )

@app.exception_handler(InsufficientStockError)
async def insufficient_stock_handler(request: Request, exc: InsufficientStockError) -> JSONResponse:
    return JSONResponse(
        status_code=status.HTTP_409_CONFLICT,
        content={
            "error": "insufficient_stock",
            "product_id": exc.product_id,
            "available": exc.available,
            "requested": exc.requested
        }
    )

Glossary

Canonical terms for this guide. Definitions state what a term is, not how to use it. Each Avoid line lists synonyms that cause confusion.

Core Concepts

ASGI
Asynchronous Server Gateway Interface — the Python async web server standard that FastAPI is built on. It is the async successor to WSGI (used by Flask and Django).
Avoid: confusing ASGI (the interface standard) with Uvicorn (an ASGI server implementation). FastAPI requires an ASGI server to run; Uvicorn is the most common choice.
path operation
FastAPI's term for a route decorated with @app.get(), @app.post(), etc. — the combination of an HTTP method and a URL path that maps to a Python function.
Avoid: "endpoint", "route", "view" — all mean the same thing across different frameworks. This guide uses "route" for brevity, but the FastAPI docs say "path operation."
Uvicorn
An ASGI server that runs FastAPI applications; it listens for HTTP connections and passes requests to the FastAPI app.
Avoid: confusing Uvicorn with FastAPI — FastAPI defines the routes and logic; Uvicorn serves them. You need both.
OpenAPI
A language-agnostic specification for describing REST APIs; FastAPI generates an OpenAPI document automatically at /openapi.json from your route definitions.
Avoid: "Swagger" as a synonym for the specification — Swagger is the tool that renders OpenAPI docs (at /docs); OpenAPI is the spec format itself.

Routing & Requests

path parameter
A variable embedded in the URL path, declared as {name} in the route string and as a matching function argument; FastAPI validates and converts its type before calling the handler.
Avoid: "URL parameter" — ambiguous, since query parameters are also in the URL. Use "path parameter" for /products/{id} and "query parameter" for /products?page=2.
query parameter
A key-value pair in the URL after ?; any function parameter not in the path template and not a Pydantic model becomes a query parameter in FastAPI.
Avoid: "GET parameter" — query parameters appear on any HTTP method, not just GET.
request body
The JSON payload sent by the client in POST, PUT, or PATCH requests; in FastAPI, declared by typing a parameter as a Pydantic model.
Avoid: "form data" unless using Form() — JSON bodies and form data are different encodings and use different FastAPI declarations.
response_model
A route parameter that names the Pydantic model FastAPI uses to serialize and filter the handler's return value before sending it to the client.
Avoid: treating response_model as an authorization mechanism — it shapes output; it does not restrict who can call the route.

Auth & Data

JWT (JSON Web Token)
A compact, self-contained token that encodes a payload (e.g., the user's email) and a signature; the server validates the signature without a database lookup, making it stateless.
Avoid: calling it a "session token" — a session token requires server-side state; a JWT does not. They solve the same problem differently.
OAuth2PasswordBearer
A FastAPI security utility that extracts a Bearer token from the Authorization header and makes it available as a dependency parameter; it does not validate the token — that is your code's job.
Avoid: confusing OAuth2PasswordBearer with a full OAuth2 implementation — it only handles token extraction, not the full OAuth2 protocol.
Depends()
A FastAPI function that declares a dependency: FastAPI calls the named function before the route handler and injects its return value as the parameter's value.
Avoid: "middleware" as a synonym — middleware wraps every request; Depends() is route-specific and composable.
dependency_overrides
A dict on the FastAPI app instance that maps a dependency function to a replacement; used in tests to swap real implementations (like get_db) with test-isolated versions.
Avoid: leaving overrides set between tests — always call app.dependency_overrides.clear() in test teardown or the override leaks into subsequent tests.
soft delete
A deletion pattern where a record is marked inactive (e.g., is_active = False) rather than physically removed from the database, preserving audit history and foreign key integrity.
Avoid: "logical delete" — same concept, but "soft delete" is the dominant term in Python/SQLAlchemy documentation.
