## Shared Datasets

Every guide's benchmark project/dataset/scenario lives in one place: [`datasets/`](datasets/README.md). This exists so no guide carries its own copy of data that could drift out of sync with another guide's copy of the "same" domain (e.g. Philippine e-commerce shows up in three separate guides).

- **Real, downloadable data** (5 guides): CSV/`.xlsx`/SQL files, deterministically generated by `datasets/gen_datasets.py` (seeded — reruns are byte-identical) or, for TindaHub, hand-authored SQL.
- **Spec-only** (10 guides): a `README.md` per project describing stack/schema/scenario facts, with no starter code — these guides teach *building* the project, so pre-built code would undercut the exercise.

Every guide's hero "how to use this guide" callout links to its subfolder in `datasets/`; the 5 real-data guides also link from their Resources → Datasets & Tools table. When generating a **new** guide with a real tabular dataset, add it to `datasets/<slug>/` (and `gen_datasets.py` if synthetic) instead of inlining data into the guide itself, and link back the same way.

## The Skill

All guides are generated by the **`/learning-guide`** Claude Code skill, defined at:

```
~/.claude/skills/learning-guide/skill.md
```

It uses a shell HTML template at:

```
~/.claude/skills/learning-guide/assets/guide_shell.html
```

The shell provides the full chrome — sidebar nav, progress meter, scrollspy JS, responsive CSS, hayah-ai branding — as a static baseline. The skill fills in content without re-writing that infrastructure.

---

## How to Generate a New Guide

Open Claude Code in any terminal and run:

```
/learning-guide <subject>
```

Examples:

```
/learning-guide react
/learning-guide "machine learning for beginners"
/learning-guide typescript --level intermediate
```

If the subject, level, or audience is ambiguous, the skill asks one round of clarifying questions before generating.

**Output path formula:**

```
/Volumes/1TB_SSD/projects-mvp-ext/learning-guides/<subject-slug>/<subject-slug>_learning_guide.html
```

## What the Skill Produces

Every generated guide includes:

- **Hero header** with an inline teal-toned SVG subject mark
- **Placement quiz** — yes/no self-assessment that routes learners to the right starting module
- **Module index** — clickable table jumping directly to any module
- **Learning tracks** — curated paths by goal (job prep, cert, skill focus)
- **Roadmap overview** — phase timeline and dependency map
- **Phases and modules** — each module has level, prereqs, estimated time, a skip-check test-out condition, and 4–8 exercise tasks
- **Phase capstones** — integrative projects per phase
- **Final capstone** — full-guide project combining all tracks
- **Quick reference** — tool–task matrix
- **Glossary** — canonical term definitions (for subjects with specialized vocabulary)
- **Resources** — books, online courses, datasets/tools, and communities
- **Progress tracker** — interactive checklist driving the sidebar progress meter

## Generation Process (Internal Phases)

The skill executes six internal phases:

| Phase | What happens |
|---|---|
| 1 — Invocation | Parse subject, level, and any inline descriptors from the command |
| 2 — Clarification | Ask only what is genuinely unclear (skipped when subject is unambiguous) |
| 3 — Planning | Determine subject type (technical vs. business/non-technical), slug, brand fields, module count, and the single benchmark dataset or scenario used across all exercises |
| 4 — Content generation | Write all HTML sections in order: hero → quick start → placement quiz → module index → tracks → roadmap → phases/modules → capstone → quick reference → glossary → resources → progress tracker → footer |
| 5 — HTML rendering | Apply ID slug formula, build nav tree in parallel with content, substitute 6 placeholders into the copied shell |
| 6 — File output | `cp` the shell to the output path, apply each Edit, run verification checks, report summary |

---

## Subject Type: Technical vs. Business

The skill detects the subject type in Phase 3 and adjusts the entire guide accordingly:

| Aspect | Technical | Business / Non-technical |
|---|---|---|
| Artifact blocks | Dark code terminal (`language-X`) | Light artifact card (`SCRIPT`, `FRAMEWORK`, `TEMPLATE`, `WORKSHEET`) |
| Running example | Benchmark dataset (e.g., "Superstore Sales") | Scenario/case (e.g., "FitForge, a $3,000 fitness offer") |
| Exercise verbs | write / run / build | draft / produce / role-play / map |
| Third resources table | Datasets & Tools | Tools & Templates |

Both types still use code blocks for actual code when it appears, and artifact cards for non-code structured content.

## Verification Checks (Automatic)

After writing the file, the skill runs these checks and fails loudly if any do not pass:

- `wc -l` — file is not truncated (floor ~1000 lines for a complete guide)
- `grep -c "{{"` — zero unreplaced placeholders
- `grep -c 'class="module-meta"'` — at least 8 modules present
- `grep -c 'id="progress-tracker"'` — progress tracker present
- `grep -c 'IntersectionObserver'` — scrollspy JS intact
- Nav/ID cross-check — every `href="#id"` and `data-href="#id"` resolves to a real `id=` in the content
- Module index uses `class="module-index-table"` with `data-href` on every row
- Hero has `.hero-mark` with an inline teal-toned SVG
