How to use this guide — you do NOT have to start at Module 1.1
This guide is built to be non-linear. Each module is self-contained with its own prerequisites, skip-check, and outcomes. Use the Placement Quiz below to find your entry point, or jump straight to any module using the Module Index. Every exercise and capstone uses the same realistic TindaHub Orders workbook — 5,000 orders from a Philippine sari-sari store distribution business. Download TindaHub_Orders.xlsx from the shared datasets folder — it ships as plain ranges (not pre-built Tables), so Module 1.3's Ctrl+T exercise still has something to do, plus a seeded RawContacts sheet, a seeded MessyImport sheet, and three raw monthly CSVs for the Power Query capstone.

How this relates to the Data Analyst guide: the Data Analyst Learning Guide in this folder covers Excel as one tool inside an analyst career path — survey-level, then moves to Power Pivot, DAX, SQL, and Python. This guide is the deep Excel-mastery companion: formulas, dynamic arrays, PivotTables, charts, and cleaning in real depth. Power Query is covered here at working-basics level only; for Power Pivot, DAX data modeling, and the full ETL toolchain, continue in the Data Analyst guide (its Modules 2.1–2.2).

Module 1.1 — Interface, Navigation & Shortcuts

Level: Beginner · Prereqs: None · Time: ~3h
Skip-check (test-out): In the TindaHub Orders sheet, jump to the last row of 5,000 orders, select the whole Amount column, and freeze the header row — all without the mouse.
Skip if: You already navigate large sheets with Ctrl+Arrow / Ctrl+Shift+Arrow and know Freeze Panes, Name Box, and multi-sheet selection.
Unlocks: 1.2

The grid, the ribbon, and where things actually live

Excel in Microsoft 365 updates monthly — the ribbon you see today includes Copilot and (on eligible plans) Python, but the core geography is stable: the Name Box (top-left) shows the active cell and accepts jump targets, the formula bar shows what a cell contains as opposed to what it displays, and the status bar gives instant Sum/Average/Count of any selection. That contains-vs-displays distinction is the single most important beginner idea: a cell showing ₱1,250.00 may contain the number 1250, a formula, or text that merely looks like a number — and each behaves differently in every later module.

Navigation shortcuts that pay for themselves forever

On a 5,000-row sheet, scrolling is a tax you pay on every task. Learn these once; they compound across every remaining module — slow navigation is why beginners avoid large datasets, and avoiding large datasets is why they stay beginners.

Ctrl+Arrow          Jump to the edge of the data block
Ctrl+Shift+Arrow    Select from here to the edge
Ctrl+Home / End     First cell / last used cell
Ctrl+T              Format the current region as a Table
Ctrl+Shift+L        Toggle filters on the header row
Ctrl+PgUp / PgDn    Previous / next worksheet
F2                  Edit the active cell (see the formula)
Ctrl+`              Show all formulas instead of results
Alt+= (Option+=)    AutoSum the obvious range
Ctrl+Z / Ctrl+Y     Undo / redo — Excel keeps ~100 steps

macOS: Cmd replaces Ctrl for most of these; Ctrl+Arrow becomes Cmd+Arrow.

Freeze Panes, split, and window discipline

View → Freeze Panes → "Freeze Top Row" keeps headers visible; "Freeze Panes" at B2 locks both the header row and an ID column. Without frozen headers you will misread which column you are in around row 800 — a classic source of silently wrong analysis, not just annoyance.

Module 1.2 — Cell References & Formula Fundamentals

Level: Beginner · Prereqs: 1.1 · Time: ~4h
Skip-check (test-out): Build a peso price list where one VAT-rate cell drives a whole column via an absolute reference, then copy the formula both down and across without breaking it.
Skip if: You can predict, before copying, how $A$1, A$1, and $A1 each shift.
Unlocks: 1.3, 1.4

Formulas are copies waiting to happen

Every formula you write will almost certainly be copied to other cells — that is Excel's whole economy. Relative references (A2) shift as the formula moves; absolute references ($A$2) stay pinned; mixed references pin only the column ($A2) or only the row (A$2). Press F4 while editing to cycle the four forms. Get this wrong and a copied formula silently reads the wrong cells — the workbook still shows numbers, just not the right ones, which is far worse than an error message.

=B2*C2          relative: each row multiplies its own Qty × UnitPrice
=B2*$F$1        absolute: every copy reads the VAT rate pinned in F1
=$A2*B$1        mixed: a multiplication grid — column A × row 1

Order of operations and the arithmetic operators

Excel follows standard precedence: parentheses, then ^, then * /, then + -, with comparison operators (= <> < > <= >=) last and & for text joining. =100+50*2 is 200, not 300. When in doubt, add parentheses — they cost nothing and every reader (including you in three months) parses the formula correctly on the first read.

The starter function set

=SUM(D2:D5001)                 total of a range
=AVERAGE(D2:D5001)             mean
=MIN(D2:D5001)  =MAX(D2:D5001) extremes
=COUNT(D2:D5001)               numeric cells only
=COUNTA(A2:A5001)              non-empty cells (any type)
=ROUND(D2*0.12, 2)             12% VAT, rounded to centavos
=TODAY()   =NOW()              current date / date-time (volatile)

COUNT vs COUNTA matters on real data: a column of order IDs stored as text gives COUNT = 0 and COUNTA = 5,000 — the mismatch itself is a data-quality signal you will exploit in Module 4.1.

Reading error values instead of fearing them

Errors are diagnostic messages, not failures. #DIV/0! — you divided by an empty or zero cell; #VALUE! — a text cell fell into arithmetic; #REF! — the formula points at cells that were deleted; #NAME? — a misspelled function or an unquoted text string; #SPILL! — a dynamic array (Module 2.4) has no room to expand. An error that shows up early is a gift; the expensive bugs are formulas that return plausible wrong numbers silently.

Module 1.3 — Excel Tables & Structured References

Level: Beginner · Prereqs: 1.2 · Time: ~3h
Skip-check (test-out): Convert the Orders range to a Table named Orders, add a calculated column, and write =SUM(Orders[Amount]) on another sheet.
Skip if: Ctrl+T is already a reflex and you prefer Orders[Amount] over D2:D5001.
Unlocks: 2.1, 2.2, 3.1, 4.1

Why Tables are the single highest-leverage habit

An Excel Table (Ctrl+T) is a range that knows its own boundaries. Formulas referencing Orders[Amount] automatically include rows added tomorrow; a plain D2:D5001 silently ignores row 5,002 forever. Most "the report missed last week's orders" incidents in real offices trace back to exactly this — a range reference that stopped growing. Tables also give you banded rows, always-on filters, a Total Row, and one-click column naming.

=SUM(Orders[Amount])                    whole column, auto-expanding
=Orders[@Qty]*Orders[@UnitPrice]        this-row reference (calculated column)
=SUM(Orders[[Qty]:[Amount]])            multi-column span
=SUBTOTAL(109, Orders[Amount])          sum of VISIBLE rows only (respects filters)

Calculated columns: one formula, every row, forever

Type a formula in the first cell of a new Table column and Excel fills the entire column and maintains it for every future row. This is the difference between a worksheet and a system: the Table enforces that every row is computed the same way, which is precisely what hand-copied formulas fail to guarantee.

Naming, Total Row, and Table hygiene

Name every Table immediately (Table Design → Table Name): Orders, Products, Customers — never Table1. The Total Row dropdown writes SUBTOTAL for you, which respects filters; a plain SUM in a total row double-counts hidden rows and no one notices until the numbers disagree with the boss's own filter. One rule: one Table per dataset, headers in row 1 of the Table, no merged cells, no blank "spacer" columns — every later tool (PivotTables, Power Query, XLOOKUP) assumes this shape.

Module 1.4 — Number Formats & Conditional Formatting

Level: Beginner · Prereqs: 1.2 · Time: ~3h
Skip-check (test-out): Build a custom format that shows ₱1,234.00 for positives, red parentheses for negatives — then a formula-driven rule that highlights whole rows where Status = "Cancelled".
Skip if: You write custom format codes and formula-based conditional formatting rules comfortably.
Unlocks: 3.3

Formatting changes the display, never the value

A cell containing 1250.5 can display ₱1,250.50, 1.25K, or 13-Jun — the stored value is identical, and every formula sees the stored value. This is why "my VLOOKUP can't find the date I'm looking at" happens: the eye compares displays, formulas compare values. When numbers look right but formulas disagree, check the format first.

Custom number format codes

A custom format has up to four sections separated by semicolons: positive; negative; zero; text.

₱#,##0.00                       ₱1,234.00  — standard peso
₱#,##0.00;[Red](₱#,##0.00)      negatives in red parentheses
#,##0,," M"                     12,400,000 → 12 M  (each comma drops 3 zeros)
0.0%                            0.1234 → 12.3%
yyyy-mm-dd                      ISO dates — sort-safe and unambiguous
[>=1000]#,##0,"K";0             1000+ shown as 1K, small numbers as-is

Use the ₱ symbol via a custom format, not by typing it into cells — ₱1,250 typed as text is a string, and your revenue column stops summing.

Conditional formatting: presets, then formulas

The presets (color scales, data bars, top 10%) cover quick looks. The real tool is "Use a formula to determine which cells to format" — the formula is written for the top-left cell of the applied range and copied conceptually across it, so reference discipline from Module 1.2 applies directly:

=$M2="Cancelled"        highlight the whole row when Status is Cancelled
                        ($ pins the column, row stays relative)
=D2>AVERAGE($D$2:$D$5001)   flag above-average order amounts
=COUNTIF($A$2:$A2,$A2)>1    flag the 2nd+ occurrence of a duplicate OrderID

Formula rules make the sheet self-monitoring: bad data lights up as it is typed, which is vastly cheaper than finding it at report time.

Module 2.1 — Logical & Lookup Functions

Level: Beginner–Intermediate · Prereqs: 1.3 · Time: ~5h
Skip-check (test-out): Pull each order's product category from the Products table with XLOOKUP, then band order amounts into Small/Medium/Large with a single approximate-match XLOOKUP — no nested IFs.
Skip if: XLOOKUP (exact, approximate, two-way, with if_not_found) is already your default and IFS/AND/OR hold no surprises.
Unlocks: 2.3, 2.4, 3.1, 4.3

IF, IFS, AND, OR — decisions in cells

=IF(Orders[@Amount]>=5000, "High", "Normal")
=IFS(Orders[@Amount]>=10000,"Large", Orders[@Amount]>=3000,"Medium", TRUE,"Small")
=IF(AND(Orders[@PaymentMethod]="COD", Orders[@Amount]>5000), "Verify", "OK")
=IF(OR(Orders[@Status]="Cancelled", Orders[@Status]="Returned"), 0, Orders[@Amount])

IFS replaces the unreadable nested-IF ladder; the final TRUE arm is its "else". Deep nesting isn't just ugly — every extra level is another place a misplaced parenthesis produces a plausible wrong answer that no error flag will catch.

XLOOKUP — the default lookup (VLOOKUP is legacy)

XLOOKUP replaced VLOOKUP as the standard in Microsoft 365. You will still read VLOOKUP in old workbooks, but write XLOOKUP: it looks in any direction, doesn't break when columns are inserted (no fragile column-number argument), and has a built-in not-found result — the three exact failure modes that made VLOOKUP infamous.

=XLOOKUP(Orders[@Product], Products[Product], Products[Category], "Unknown")
   lookup_value, lookup_array, return_array, [if_not_found]

Approximate match (banding — match_mode -1 = next smaller):
=XLOOKUP(Orders[@Amount], {0;3000;10000}, {"Small";"Medium";"Large"}, , -1)

Two-way lookup (row AND column):
=XLOOKUP($B3, Products[Product], XLOOKUP(C$2, {"Cost","Price"}, ...))
  — or simpler with INDEX/MATCH:
=INDEX(RateGrid, MATCH($B3, ProductList, 0), MATCH(C$2, HeaderRow, 0))

Always supply if_not_found. Without it a missing product returns #N/A, which then poisons every SUM downstream — one unmatched row can blank an entire report total.

INDEX and MATCH — still worth knowing

INDEX/MATCH predates XLOOKUP and remains everywhere in inherited workbooks; MATCH also feeds other functions (like picking a column dynamically). =INDEX(return_range, MATCH(value, lookup_range, 0)) is the exact-match idiom; the 0 is mandatory — omit it and MATCH silently does an approximate match on unsorted data, returning confidently wrong rows.

Common mistake: VLOOKUP's fourth argument defaults to approximate match (TRUE). Every legacy VLOOKUP without an explicit FALSE is a latent bug on unsorted data — it returns a nearby value, not an error, so the report looks fine and is wrong. When auditing an inherited workbook, search for VLOOKUP( and check every fourth argument first.

Module 2.2 — Text, Date & Time Functions

Level: Beginner–Intermediate · Prereqs: 1.3 · Time: ~4h
Skip-check (test-out): Split "Lopez, Maria | Quezon City" into clean name and city columns with TEXTSPLIT/TEXTBEFORE, and compute each order's fulfilment age in days excluding Sundays.
Skip if: TEXTSPLIT/TEXTBEFORE/TEXTAFTER, TEXT(), EOMONTH, NETWORKDAYS.INTL, and the serial-date model are all familiar.
Unlocks: 4.1

Dates are numbers wearing costumes

Excel stores dates as serial numbers (day 1 = 1900-01-01) and times as day-fractions — noon is 0.5. That's why dates subtract cleanly (=B2-A2 gives days) and why a "date" that won't subtract is actually text: imported CSVs are the usual culprit, and a column that is half real dates, half text-dates will sort into two separate blocks and split your monthly totals in ways that look like a business trend.

=DATE(2026,7,17)        build a date from parts
=YEAR(A2) =MONTH(A2) =DAY(A2) =WEEKDAY(A2,2)   decompose (WEEKDAY 2: Mon=1)
=EOMONTH(A2,0)          month-end of A2   (EOMONTH(A2,-1)+1 = month start)
=EDATE(A2,3)            same day 3 months later
=NETWORKDAYS.INTL(A2,B2,11)   working days, 11 = Sunday-only weekend (PH retail)
=TEXT(A2,"yyyy-mm")     month key for grouping — returns TEXT, fine for labels

Modern text functions

Microsoft 365 replaced most LEFT/MID/FIND gymnastics with direct tools:

=TEXTBEFORE(A2,",")               "Lopez, Maria" → Lopez
=TEXTAFTER(A2,", ")               "Lopez, Maria" → Maria
=TEXTSPLIT(A2," | ")              one cell → several spilled columns
=TEXTJOIN(", ",TRUE,B2:D2)        join with delimiter, skip blanks
=TRIM(A2)  =CLEAN(A2)             kill stray spaces / non-printing chars
=UPPER(A2) =LOWER(A2) =PROPER(A2) case repair
=SUBSTITUTE(A2,"₱","")           strip a character everywhere
=VALUE(A2)                        text-number → real number

Legacy LEFT/RIGHT/MID/FIND/LEN still matter for reading old workbooks, but write the modern forms — they say what they mean.

Pattern matching with the REGEX functions

Excel now ships regular expressions natively (generally available in Microsoft 365) — no VBA required:

=REGEXTEST(A2,"^09\d{9}$")            valid PH mobile number? (09XXXXXXXXX)
=REGEXEXTRACT(A2,"\d{4}-\d{4}")       pull an order ref like 2026-0417
=REGEXREPLACE(A2,"\s+"," ")           collapse repeated spaces to one

Validating phone formats at entry beats discovering at campaign time that a fifth of your Viber list is undeliverable.

Module 2.3 — Conditional Aggregation

Level: Beginner–Intermediate · Prereqs: 2.1 · Time: ~4h
Skip-check (test-out): One formula: June 2026 revenue for Region "NCR", GCash payments only, products starting with "Lucky". If SUMIFS with date bounds and a wildcard is routine, skip.
Skip if: SUMIFS/COUNTIFS/AVERAGEIFS with multiple criteria, date boundaries, and wildcards are muscle memory.
Unlocks: 2.4, Capstone 2

The IFS family — filters built into the math

=SUMIFS(Orders[Amount], Orders[Region],"NCR")
=SUMIFS(Orders[Amount], Orders[Region],"NCR", Orders[PaymentMethod],"GCash")
=COUNTIFS(Orders[Status],"Cancelled", Orders[Amount],">5000")
=AVERAGEIFS(Orders[Amount], Orders[Category],"Beverages")

Criteria pairs are AND-ed: every pair must hold for a row to count. Ranges must be the same height — a mismatched range doesn't error, it misaligns rows against criteria and quietly produces garbage, which is why building these from Table columns (always equal height) is safer than hand-picked ranges.

Date-bounded sums — the month-report idiom

=SUMIFS(Orders[Amount],
        Orders[OrderDate], ">=" & DATE(2026,6,1),
        Orders[OrderDate], "<"  & DATE(2026,7,1))

Two criteria on the same date column bracket the month. Prefer >= first-day AND < next-month-first-day over <= month-end: it's immune to stray time-of-day fractions in the data (an order stamped June 30 14:32 is after June 30 00:00 and falls out of a <=EOMONTH bracket).

Wildcards and criteria cells

"Lucky*"     starts with Lucky      "*Noodles"   ends with
"*Corned*"   contains               ">="&$B$1    operator joined to a cell

Concatenating operators to cell references (">="&$B$1) turns a hard-coded report into a parameterized one — change the threshold cell, the whole report follows. Hard-coded criteria scattered through formulas are the reason month-end updates take hours instead of seconds.

SUBTOTAL and AGGREGATE — math that respects filters

=SUBTOTAL(109, Orders[Amount]) sums only visible rows; function 9 vs 109 differs in whether manually hidden rows count. =AGGREGATE(9, 6, range) adds the superpower of ignoring error values — a single #N/A in 5,000 rows kills SUM but not AGGREGATE with option 6.

Module 2.4 — Dynamic Arrays & Spilling

Level: Intermediate · Prereqs: 2.1 · Time: ~5h
Skip-check (test-out): One formula that returns all NCR orders above ₱3,000 sorted by amount descending, and a second cell that counts them via the # spill reference.

Unlocks: 2.5

One formula, many answers

Dynamic arrays changed Excel's grammar: a formula can now return a whole block of results that spills into neighboring cells. The formula lives only in the top-left cell; the rest is ghost output you cannot edit. This eliminates the copy-down step — and the entire class of bugs where someone copied a formula down 4,998 rows instead of 5,000.

=UNIQUE(Orders[Region])                          distinct regions, spilled
=SORT(UNIQUE(Orders[Category]))                  distinct + alphabetical
=FILTER(Orders, Orders[Region]="NCR", "none")    all NCR rows
=SORT(FILTER(Orders[Amount], Orders[Amount]>3000), 1, -1)   big orders, desc
=SEQUENCE(12,1,DATE(2026,1,1),31)                quick 12-month scaffold (approx)
=SUMIFS(Orders[Amount], Orders[Region], E2#)     criteria = a whole spill range

The # operator — reports that grow themselves

E2# means "E2's entire spill, however big it is today." Put =UNIQUE(Orders[Region]) in E2 and =SUMIFS(Orders[Amount], Orders[Region], E2#) beside it, and you have a region report that automatically gains a row the day a new region appears in the data — no maintenance, ever. This UNIQUE-plus-SUMIFS pair is the modern replacement for hand-built summary tables.

#SPILL! and the blocked-range rule

#SPILL! means the output needs room that something occupies — often a stray value cells away, or the formula sits inside an Excel Table (Tables can't hold spills; put spill formulas on report sheets, Tables hold source data). Click the error's dashed outline to see exactly what's in the way.

Disambiguation: "Array formula" historically meant the legacy Ctrl+Shift+Enter (CSE) {...} formulas. Dynamic arrays replace those — never write CSE in Microsoft 365. If you see braces in an inherited workbook, that's the old dialect; rewriting it as a spilling formula is usually shorter and faster.

LET — name your steps

=LET(
   ncr,    FILTER(Orders[Amount], Orders[Region]="NCR"),
   total,  SUM(ncr),
   cnt,    ROWS(ncr),
   TEXT(total,"₱#,##0") & " across " & cnt & " orders"
 )

LET binds names to intermediate results, so a sub-expression is computed once and read many times. Beyond speed, it makes formulas reviewable — a colleague (or an auditor) can read ncr, total, cnt as a story instead of re-parsing a nested one-liner three times.

LAMBDA — your own functions, no VBA

Name Manager → New:  PesoBand
=LAMBDA(amt, IFS(amt>=10000,"Large", amt>=3000,"Medium", TRUE,"Small"))

Then anywhere in the workbook:
=PesoBand(Orders[@Amount])

Business logic defined once in Name Manager instead of pasted into 5,000 cells: when the banding thresholds change (they will), you edit one definition and the whole workbook follows. Copy-pasted logic drifts — two "identical" formulas that were edited separately is a classic month-end reconciliation nightmare.

GROUPBY and PIVOTBY — pivot-shaped answers as formulas

These aggregation functions (now generally available in Microsoft 365) produce grouped summaries that spill and refresh instantly with the data — no "Refresh" click, which is the operational difference from PivotTables (Module 3.1 covers when each wins):

=GROUPBY(Orders[Region], Orders[Amount], SUM)
   one row per region with total — like a mini pivot, always live

=PIVOTBY(Orders[Region], Orders[PaymentMethod], Orders[Amount], SUM)
   regions down, payment methods across, sums in the grid

The third argument takes any aggregation eta-lambda (SUM, AVERAGE, COUNT, or a custom LAMBDA). Use GROUPBY/PIVOTBY for live in-sheet summaries; use PivotTables when you need interactive exploration, slicers, or drill-down.

What a PivotTable actually is

A PivotTable is a summarization engine over a snapshot of your source: drag fields into Rows, Columns, Values, and Filters, and it groups and aggregates without a single formula. The snapshot part is the operational catch — a pivot reads a cached copy, so new source rows do not appear until you Refresh (right-click → Refresh, or Data → Refresh All). Presenting an unrefreshed pivot is the most common way a correct workbook produces a wrong meeting.

Always build pivots from a named Table (Module 1.3), never a raw range: the Table's auto-expansion is what guarantees Refresh actually sees new rows.

Building the canonical revenue pivot

Insert → PivotTable → from Table: Orders → New Worksheet

Rows:    Region
Columns: OrderDate  (Excel auto-groups → keep Months, remove Quarters)
Values:  Amount     (Sum)
Filters: Category

Value Field Settings → Number Format → ₱#,##0
  — format the FIELD, not the cells: it survives every layout change

Sorting, grouping, and layout

Right-click any value → Sort → Largest to Smallest reorders the whole row axis by the numbers. Date grouping (Years/Quarters/Months) is automatic on real dates — if grouping is greyed out, the column contains text-dates, and you have a Module 4.1 problem, not a pivot problem. Under Design, prefer Tabular layout with "Repeat All Item Labels" when anyone will copy the pivot's output elsewhere; the default Compact layout reads well but exports badly.

Count, average, and the drilldown

Drag Amount into Values a second time and set it to Average — one pivot, two lenses. Double-click any value cell to drill through: Excel spills the underlying source rows onto a new sheet, which is both the fastest audit tool in Excel and the fastest way to answer "which orders make up this number?"

Slicers and timelines — filters you can hand to a manager

Insert → Slicer creates clickable filter buttons; Insert → Timeline does the same for date ranges. Their superpower is Report Connections (right-click the slicer): one slicer can drive every pivot on a dashboard simultaneously, which is what turns three separate pivots into one coherent, explorable page. A dashboard whose charts filter independently is worse than no dashboard — two charts silently showing different slices is how wrong conclusions get projected on meeting-room walls.

Show Values As — the analysis layer

Right-click a value → Show Values As transforms the same Sum into a different question, with zero helper columns:

% of Grand Total       each region's share of the business
% of Column Total      composition within each month
Running Total In       cumulative revenue across OrderDate
Difference From        month-over-month change (Base: previous)

Drag Amount into Values twice — raw Sum beside % of Column Total — and one pivot answers "how much and what share" at once.

Calculated fields, and when to walk away

PivotTable Analyze → Fields, Items & Sets → Calculated Field lets you define e.g. = Amount / Qty inside the pivot. Know the limit: calculated fields operate on sums of fields (SUM(Amount)/SUM(Qty) — a weighted average, often what you want, sometimes not) and cannot reference individual rows. When a calculation needs row-level logic, add it as a Table calculated column (Module 1.3) or move to Power Pivot measures — that road continues in the Data Analyst guide, Module 2.2, and is deliberately not duplicated here.

GETPIVOTDATA — stable cell references into a pivot

Typing = and clicking a pivot cell writes =GETPIVOTDATA("Amount", $A$3, "Region", "NCR", ...). Reflex is to hate it; the reflex is wrong for report sheets. A plain =B7 into a pivot breaks the moment the layout shifts one row; GETPIVOTDATA keeps pointing at "NCR revenue" by name, whatever the layout. Use it to feed stable KPI cells from a living pivot.

Chart choice is a sentence, not a decoration

Decide what the chart must say, then pick the form that says it:

Comparison across categories   → bar (horizontal if labels are long)
Trend over time                → line
Composition (few parts)        → stacked bar / 100% stacked
Relationship of two measures   → scatter
Distribution                   → histogram / box & whisker
Single KPI vs target           → simple number + delta, not a gauge

Pie charts survive only with 2–3 slices; human eyes rank angles poorly, which is why a sorted bar chart beats a 7-slice pie every time it is tried. A chart that needs its legend studied has already failed its ten-second test — the audience decides in that window whether the dashboard is trustworthy.

PivotCharts — charts that obey slicers

A PivotChart is bound to its PivotTable, so the slicers and timeline from Module 3.2 drive it automatically — that combination (pivots + slicers + pivot charts) is the entire mechanical basis of an interactive Excel dashboard. Field buttons on the chart are for building, not presenting: right-click → Hide All Field Buttons before anyone sees it.

Declutter, then emphasize

Delete gridlines, borders, and the legend where a direct label works; start bar axes at zero (a truncated axis manufactures drama the data doesn't contain); use one emphasis color against grey rather than a color per series. Formatting is information triage — every pixel that isn't the message is competing with it.

Dashboard assembly

One screen, no scrolling: KPI row on top (GETPIVOTDATA-fed cells), one trend chart, one comparison chart, one composition view, slicers along an edge, all pivots hidden on a back sheet. Lock the layout mentally to a grid; snap objects with Alt-drag. The test of a good dashboard is that the manager finds next month's answer without asking you.

The four horsemen of dirty spreadsheet data

Text-numbers (left-aligned, excluded from SUM — fix with VALUE or multiply-by-1), stray spaces ("NCR " ≠ "NCR" to every lookup and SUMIFS — fix with TRIM), duplicates (Data → Remove Duplicates, but count first with COUNTIF so you know what you deleted), and inconsistent categories ("QC", "Quezon City", "quezon city" are three cities to a PivotTable). Each is invisible in a casual scroll and each silently corrupts every aggregate downstream — cleaning is not preparation for analysis, it is analysis of what can go wrong.

=ISNUMBER(D2)                          FALSE = text-number lurking
=LEN(C2)-LEN(TRIM(C2))                 >0 = stray spaces
=COUNTIF(Orders[OrderID],[@OrderID])   >1 = duplicate
=SORT(UNIQUE(Orders[City]))            eyeball the spelling variants in one list

Find & Replace, Flash Fill, and text-to-columns

Ctrl+H with "Match entire cell contents" standardizes category variants safely. Flash Fill (Ctrl+E) learns a pattern from one or two examples — type Maria Lopez beside LOPEZ, MARIA | QC, press Ctrl+E, and it rewrites the column. Flash Fill output is static values (it will not update with new data) — perfect for one-off repairs, wrong for recurring imports, which is exactly the line where Power Query (Module 4.2) takes over.

Data Validation — stop bad data at the door

Data → Data Validation:
  List      =StatusList           dropdown: Delivered/Pending/Cancelled/Returned
  Date      between 1/1/2024 and =TODAY()      no future orders
  Custom    =COUNTIF(Orders[OrderID],A2)=1     reject duplicate IDs at entry
  Custom    =REGEXTEST(B2,"^09\d{9}$")         PH mobile format only

Source the dropdown list from a small Table so new statuses are one row away. Every validation rule is a cleaning task you never do again: the economics of prevention over repair is the entire lesson of this module.

Recorded cleaning that replays forever

Power Query (Data → Get Data) is a step recorder for data preparation: every transform you click becomes a named step in Applied Steps, and the whole recipe replays on Refresh. This flips the cleaning economics of Module 4.1 — instead of repairing March's file and repairing April's file again, you repair the pipeline once. If you clean the same shape of file twice, you were supposed to use Power Query the first time.

Data → Get Data → From File → From Text/CSV → Transform Data

Typical applied steps for a TindaHub monthly CSV:
  Promoted Headers        first row → column names
  Changed Type            OrderDate → Date, Amount → Currency
  Trimmed Text            City, Customer
  Replaced Values         "QC" → "Quezon City"
  Filtered Rows           remove Status = "Test"
  Removed Duplicates      on OrderID

Set data types deliberately — with a PH-format file, use "Changed Type with Locale" when dates arrive as dd/mm/yyyy; letting the type guesser misread day-month order is the classic silent import bug.

Append and merge — the two joins that matter

Append stacks same-shaped tables (Jan + Feb + Mar orders → one table). Merge joins on a key (Orders + Products on Product → categories flow in), with join kinds mirroring SQL: Left Outer keeps all orders and blanks the misses — and expanding only the columns you need keeps the result lean. Better still, From Folder appends every file in a directory automatically: drop 2026-07.csv in, press Refresh, done — that single pattern replaces hours of monthly copy-paste in most small businesses.

A first look at M (and where this road leads)

Every query is M code under Advanced Editor — readable, worth skimming so applied steps stop being magic:

let
    Source = Csv.Document(File.Contents("C:\TindaHub\2026-06.csv")),
    Headers = Table.PromoteHeaders(Source),
    Typed = Table.TransformColumnTypes(Headers,
              {{"OrderDate", type date}, {"Amount", Currency.Type}}),
    Clean = Table.TransformColumns(Typed, {{"City", Text.Trim}})
in
    Clean

This guide deliberately stops at working basics. Query folding, parameters, custom M functions, and the Power Pivot/DAX layer that consumes these queries are covered in the Data Analyst guide (Modules 2.1–2.2) — go there when a merge-and-append pipeline stops being enough.

Auditing: follow the dependency chain

Formulas → Trace Precedents draws arrows from a cell to everything it reads; Trace Dependents shows what would break if you changed it — check dependents before editing any cell in a workbook you didn't build. Evaluate Formula steps through a calculation one operation at a time, which is how you find the exact point a nested formula goes wrong instead of staring at it. Ctrl+` (formula view) plus Find can locate every hard-coded constant hiding where a reference should be — the archaeology of inherited workbooks.

Error handling as policy, not decoration

=IFERROR(XLOOKUP(...), "—")     display fallback for report cells
=IFNA(XLOOKUP(...), 0)          catches ONLY #N/A — a typo still errors loudly
=ISBLANK(A2)  =ISNUMBER(A2)     test before you compute

Prefer IFNA for lookups: it absorbs the expected miss (#N/A) while letting genuine formula bugs (#VALUE!, #REF!) stay visible. A blanket IFERROR over everything is how workbooks hide their own defects — you are choosing which errors deserve silence, and that choice should be narrow.

Protection and the input/logic/output contract

Structure every shipped workbook in three layers: input cells (unlocked, visibly styled), logic (locked, often on hidden sheets), outputs (locked). Then Review → Protect Sheet. All cells are locked by default, so the workflow is: select input cells → Format Cells → uncheck Locked → protect the sheet. This isn't security (Excel sheet passwords are trivially stripped) — it's a guardrail against the accidental Tuesday keystroke that overwrites a formula, which is a far more common cause of workbook death than malice.

Named ranges and the ReadMe habit

Name Manager (Ctrl+F3) turns $F$1 into VATRate — formulas become sentences (=Amount*VATRate) and the definition is documented in one place. Pair it with a ReadMe sheet: data sources, refresh steps, owner, and the date convention (Module 2.3's bracket rule). The workbook that only its author can operate dies with its author's job change.

Glossary

Canonical terms for this guide. Definitions state what a term is, not how to use it. Each Avoid line lists synonyms that cause confusion.

Grid & References

Cell reference
The address of a cell (B2) or range (B2:D10) as used inside a formula.
Avoid: "cell name" — a name is a Name Manager label; a reference is an address.
Absolute / relative reference
Whether a reference stays pinned ($B$2) or shifts (B2) when its formula is copied to another cell.
Avoid: "locked cell" — locking is a protection feature, unrelated to $.
Excel Table
A structured range (Ctrl+T) with a name, auto-expanding boundaries, and column-name references.
Avoid: "table" for any rectangle of cells — a formatted range without Ctrl+T has none of the Table behaviors.
Structured reference
A formula reference by Table and column name, e.g. Orders[Amount] or this-row [@Qty].
Avoid: "named range" — names are defined in Name Manager; structured references come free with Tables.
Named range / defined name
A label defined in Name Manager that stands for a cell, range, constant, or LAMBDA.
Avoid: conflating with Table names — Tables appear in Name Manager but behave differently.
Serial date
Excel's internal storage of a date as a number of days since 1900-01-01, with times as day-fractions.
Avoid: "timestamp" for the display format — the format is costume; the serial is the value.
Number format
A display rule (e.g. ₱#,##0.00) that changes how a value looks without changing the value.
Avoid: "formatting the data" — formats never alter stored values; VALUE/TEXT conversions do.
Volatile function
A function (TODAY, NOW, RAND, OFFSET, INDIRECT) that recalculates on every workbook change.
Avoid: "dynamic function" — dynamic arrays are a different, unrelated concept.

Formulas & Arrays

Spill / spill range
The block of cells a dynamic-array formula fills below and beside its home cell; referenced whole via #.
Avoid: "overflow" — #SPILL! is blocked spilling, not numeric overflow.
Dynamic array formula
A formula (FILTER, SORT, UNIQUE, SEQUENCE, GROUPBY…) whose result is a spilling array rather than one value.
Avoid: "array formula" alone — that historically means legacy Ctrl+Shift+Enter formulas, now obsolete.
Criteria pair
A range-plus-condition argument couple in the IFS aggregation family (Orders[Region],"NCR"); pairs are AND-ed.
Avoid: "filter" — worksheet filters hide rows; criteria pairs select rows inside one calculation.
LAMBDA
A user-defined function written in formula language and (usually) registered under a name in Name Manager.
Avoid: "macro" — macros are VBA procedures; LAMBDAs are pure formulas with no security prompts.
LET binding
A name-value assignment inside a LET formula, computed once and reused within that formula only.
Avoid: "variable" without qualification — LET names are per-formula, not workbook-wide.
Lookup
Retrieving a value from one table by matching a key against another column (XLOOKUP, INDEX/MATCH).
Avoid: "vlookup" as a generic verb — say lookup; VLOOKUP is one legacy implementation.
Approximate match
A lookup mode returning the nearest value at-or-below (or above) the key — the mechanism behind banding tables.
Avoid: "fuzzy match" — fuzzy matching (typo-tolerant text) is a Power Query feature, entirely different.
Wildcard
The * (any characters) and ? (one character) placeholders accepted by criteria and some match modes.
Avoid: "regex" — wildcards are far weaker; REGEXTEST is the real pattern engine.

Pivots, Charts & Cleaning

PivotTable
An interactive summarization object that groups and aggregates a cached snapshot of a source table.
Avoid: "pivot" for PIVOTBY — the function is live and formula-based; the PivotTable is cached and interactive.
Pivot cache
The stored copy of source data a PivotTable actually reads; stale until Refresh.
Avoid: assuming "live" — every pivot number is as old as its last refresh.
Slicer / timeline
On-sheet filter controls (buttons / date band) that can drive one or many PivotTables via Report Connections.
Avoid: "filter dropdown" — the header dropdown filters one pivot only and hides its state.
Show Values As
A value-field display transform (% of total, running total, difference from) computed inside the pivot.
Avoid: "calculated field" — that is a different feature defining new formulas over summed fields.
Drillthrough
Double-clicking a pivot value to spill its underlying source rows onto a new sheet.
Avoid: "drill down" — drill down expands a hierarchy level in place; drillthrough extracts rows.
Query (Power Query)
A recorded sequence of applied transform steps, written in M, that replays against sources on Refresh.
Avoid: "macro" — no VBA involved; and "SQL query" — M is a different language and model.
Append vs Merge
Append stacks same-shaped tables vertically; Merge joins two tables sideways on a key column.
Avoid: "combine" unqualified — the two operations answer different questions and are not interchangeable.
Data Validation
Cell-entry rules (lists, bounds, custom formulas) that reject invalid input at typing time.
Avoid: "conditional formatting" — CF colors what already got in; validation stops it getting in.
Refresh
The command that re-reads sources: replays Power Query steps and rebuilds pivot caches.
Avoid: "recalculate" (F9) — recalculation reruns formulas; Refresh re-reads external/cached data.
