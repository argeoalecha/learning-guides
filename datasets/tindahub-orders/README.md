# TindaHub Orders

Used by: **[Excel guide](../../excel/excel_learning_guide.html)** (every module and capstone)

The flat, 5,000-row order register the Excel guide calls the "TindaHub Orders workbook" throughout — a Philippine sari-sari store distribution business. Distinct from [`tindahub/`](../tindahub/) (the normalized 6-table SQL schema used by the postgresql-metabase guide) — same fictional business, different shape: this one is a deliberately flat, single-table-per-sheet register because the Excel guide teaches Tables, lookups, and PivotTables, not joins.

Every sheet ships as a **plain range**, not a pre-built Excel Table — Module 1.3's first exercise is converting `Orders`/`Products`/`Customers` to named Tables with Ctrl+T, so pre-Tabling them would rob the exercise.

## Sheets in `TindaHub_Orders.xlsx`

**`Orders`** (5,000 rows) — `OrderID, OrderDate, Customer, Barangay, City, Province, Region, Product, Category, Qty, UnitPrice, Amount, PaymentMethod, Status, DeliveredDate, ImportedDates`. Jan–Jun 2026, 6 regions (NCR, Central Luzon, CALABARZON, Central Visayas, Davao Region, Western Visayas), 26 products across 6 categories (Noodles & Canned Goods includes "Lucky Me..." and "...Corned Beef" products for the guide's wildcard-criteria examples). `DeliveredDate` is blank for Pending/Cancelled orders. `ImportedDates` is the same calendar date as `OrderDate` but stored as **text** in `dd/mm/yyyy` format — Module 2.2's exercise is converting the whole column to real dates.

**`Products`** (26 rows) — `Product, Category, UnitPrice`. Master price list; the source Module 4.2's Power Query merge pulls `Category` from.

**`Customers`** (200 rows) — `CustomerID, Name, Mobile, Barangay, City, Province, Region, JoinDate`. Every `Orders` row's location fields trace back to one of these customers.

**`RawContacts`** (60 rows) — `RawEntry, Mobile`. `RawEntry` jams `"Surname, FirstName | City"` into one column, mixed-case, with stray spaces — Module 2.2's TEXTSPLIT/TRIM/PROPER exercise. `Mobile` is ~80% valid PH format (`09XXXXXXXXX`) and ~20% seeded invalid (missing digit, `+63` prefix, letters) for the REGEXTEST exercise.

**`MessyImport`** (500 rows) — `OrderID, OrderDate, Customer, City, Region, Product, Qty, UnitPrice, Amount, Mobile, PaymentMethod, Status`. Seeded for Module 4.1: 15 duplicate `OrderID`s (known ground truth — audit with `COUNTIF` before removing, and confirm the count matches), ~15% of `Amount` stored as text-numbers, ~25% of `Customer` padded with stray spaces and upper-cased, city-name variants (`"Quezon City"` / `"QC"` / `"quezon city"`, similarly for Manila and Cebu City), ~3% of `OrderDate` seeded in the future (Dec 2026) to trip the no-future-dates validation rule, and a handful of malformed `Mobile` values.

## Monthly CSV extracts (`tindahub_2026-04/05/06.csv`)

Raw shape as they'd arrive from a POS export — **no `Category` column** (Module 4.2 merges it in from `Products`), `OrderDate` as `dd/mm/yyyy` text (PH locale — the "Changed Type with Locale" teaching point), a few `Status = "Test"` rows to filter out, and 4 duplicate `OrderID`s seeded within each file (the "Removed Duplicates" applied step). Row counts: 320 / 345 / 360 — verify Power Query's appended total equals the sum after building the From Folder query.

## Seeded ground truth (for grading / self-check)

- `Orders`: exactly **3** rows where `Amount ≠ Qty × UnitPrice` (Module 1.3's `LineCheck` exercise), exactly **8** duplicate `OrderID`s (conditional-formatting exercise).
- `MessyImport`: exactly **15** duplicate `OrderID`s.
- Each monthly CSV: exactly **4** duplicate `OrderID`s within the file.
